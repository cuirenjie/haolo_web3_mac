# 历史上下文与积分消耗优化（CREDITS-CONTEXT-20261025）

状态：本地实现、真实计费模型对照及回归验证；尚未发布客户端。范围为共享请求传输与背景去重，不改变量化引擎、行情选择、策略、账户授权、输出额度或商品费率。提前 128K 整理实验未通过，已撤回；最终结果见 `context-model-validation-20261025.zh-CN.md`。

## 证据与原因

客户账单的只读核查记录在规范前端仓库 `docs/credit-exhaustion-investigation-20261025.zh-CN.md`。
553 次请求属于 85 个有标识的轮次、11 个会话；累计未缓存输入约 2490 万 token、缓存输入约 3307 万 token，输出约 19.7 万 token。未发现相同请求重复入账，但这不能证明每次输入都必要。

普通工具循环的下一次推理需要此前消息、工具调用和结果；即使缓存命中，产品费率也不是零。网络 zstd 压缩只能减少传输字节，不能减少上游解压后看到的 token。用量表没有保存客户完整请求正文，因此不能推断该客户具体重复了哪些报告或承诺补回多少积分。

源码中确认两个重复来源，并评估了整理阈值：

1. `analysisEvidence` 单报告结果同时返回 `result.report` 与 `result.reports[0].report`，两者正文完全相同。这些字段随工具历史反复进入后续推理。类似的 JSON 工具结果还可能携带其他完全相同的长字符串。
2. GPT 托管目录以 300,000 token 触发整理；DeepSeek 的厂商目录没有显式整理阈值，Renderer 从 1M 容量推导出 943,718 token。这是容量保护，不能据此直接推断更低阈值一定省积分。真实实验中提前整理破坏缓存并增加付费调用，候选已撤回。
3. 同组会话背景扫描没有排除当前会话，会把当前任务的截短消息再当作“其他任务”放进 developer 前缀；它们本来已经在原生历史中。

## 实现

- `model-context-projection.mjs` 只处理托管请求中的工具结果。单个 JSON 结果内相同的长字符串保留第一份原文，其他位置改为指向同一结果中原文的 JSON Pointer，并提供显式编码说明。引用不跨请求、不跨结果、不跨用户；每次观察的调用 ID、时间、市场、周期、数字、状态与不同的正文都保留。无需模型摘要、取文件、联网或重跑工具。
- 只投影发往模型的请求副本。持久化历史、原始工具结果和展示卡片不改；用户消息、助手消息、系统指令、工具参数、工具定义与加密推理均不处理。支持 Responses、WebSocket 信封、MCP 文本包装、工具文本块及 Chat 工具消息。未知格式、已有冲突标记、过深或过大结构保持原样。投影幂等，追加新轮次不会改写旧请求前缀。
- 接入已有真实 relay 的 HTTP/WS 边界，先解包现有 gzip/deflate/br/zstd，再投影并保留编码；独立模型不启用。只输出字节、引用和结果数量的日志，不记录正文、账号或凭据。`HAOLO_DESKTOP_CONTEXT_PROJECTION=0` 可关闭投影，不影响模型选择或计费合同。
- 不启用提前语义摘要或 128K 整理策略。主进程与 Renderer 已恢复既有容量阈值；本任务新增的共享阈值模块和相关入口改动已删除，用户自定义配置保留。GPT 400K / DeepSeek 1,048,576 原生容量保持。
- 保留原生上下文整理、成功事件等待、历史落盘和失败恢复机制，不删除历史、不按固定轮数截断。真实长会话复测验证未额外整理，仍能保留任务事实、最新修正和未完成事项。
- 普通发送入口显式传递其持有的 thread ID，`group-memory-context.mjs` 从同组背景扫描中排除当前 rollout。其他任务背景保留；未知 ID 不猜测匹配，不依赖 UI 的全局当前任务。只避免重复读取与注入，不删除任何历史文件。

## 验证及限度

无网络模型调用的可复现实验使用真实 `analysisEvidence` 函数和合成中文报告；样例不是客户正文。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 工具结果 UTF-8 字节 | 30,119 | 15,543 |
| 客户端文本 token 估算 | 9,195 | 4,719 |

去掉 14,576 字节（48.3947%）。独立测试解码器可逐字段还原完整原对象，包括未知字段、中文、JSON Pointer 特殊键、市场周期、条件、缺失账户状态与观察时间。估算不是模型 tokenizer 或实际账单，不能外推为整次请求或客户积分节省比例。

回归覆盖五种编码、HTTP/WS 实际本地 relay、流式响应、工具配对、图片保留、重放前缀稳定、停用开关、私有模型隔离、超深结构、原生容量、旧配置同步、压缩失败/迟到通知/恢复。机器可还原不等于模型一定正确理解；因此另做真实模型对照，失败候选和修正前的评分记录均保留。

验收：227 项请求、历史、整理与恢复回归，以及 30 项同组背景、频道隔离、原生串行入口与编码回归通过；4 项客服知识测试通过；Renderer 类型检查通过。主回归包括自带原生运行时的三种历史存储布局测试，验证真实历史初始化与后续消息保留。初次扩展回归发现并修正了 VM 测试加载器对共享模块的兼容，以及既有路由档位变化后的旧断言，最终均通过。

静态报告：仓库根 `output/context-efficiency-20261025/benchmark.json`。真实对照：`output/context-model-ab-20261025/`。最终方案 26 个答案通过事实和连续性检查；去重样本积分下降 13.07%，背景去重联合样本下降 32.01%；无重复长会话积分增加 0.87%，没有额外整理，不能承诺每次调用都省积分。上述样本不是客户原始请求，也不是统计意义上的全面无退化证明。

## 交付边界

本任务没有提交、推送、打包、生产部署或客户积分变更。共享工作区另有模型路由修复；发布候选必须审查其完整依赖与本任务差异，不能仅复制投影文件而遗漏 `model-request-policy` / relay 接线。遵守跨会话发布规范和客户端签名发布流程。源码修改不代表已到达客户安装版本。
