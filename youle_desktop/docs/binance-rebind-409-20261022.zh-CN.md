# Binance 解绑后重新绑定的 409 修复

2026-10-22。状态：源码修复与本地验收完成，未部署后端、未发布 Windows 安装包。

## 根因与处理

生产只读诊断发现，Windows 用固定的设备级幂等键创建账户连接。连接解绑后，后端仍从幂等缓存返回旧连接的初始结果，随后提交密钥被 `CONNECTION_REVOKED` 拒绝。客户端保留了错误码，却把提示降为 `HTTP 409`。

- Windows 每次新建连接生成独立幂等键；调用方显式传入的键仍用于同一次操作重试。移除绑定过程中的重复注册／创建调用，继续先验证交易所、邮箱及共享凭据，再保存本地凭据。
- 后端对旧客户端固定键做兼容：在用户事务锁内检查缓存引用的连接；若已撤销，创建新连接并原子更新该键的响应。旧连接保持撤销，旧凭据、历史、授权和任务不恢复。请求内容冲突、账号隔离和活跃连接数量上限保持。
- 连接已解绑、尚未完成绑定、连接数量上限、设备数量上限、幂等冲突显示具体处理提示，覆盖简中、英文、繁中。后端绑定接口的撤销错误也提供三语文字。
- 错误提示使用既有危险操作文字色，亮色／暗色实测对比度分别为 5.02:1／5.30:1。

后端实现与数据库集成测试位于 `D:/haolo_front_web3/youle_mas-dev/backend`，详见该仓库 `docs/binance-rebind-409-20261022.md`。
