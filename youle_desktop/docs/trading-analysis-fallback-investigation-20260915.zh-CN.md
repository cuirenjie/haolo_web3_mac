# “指定分析增强暂时不可用”排查记录

日期：2026-09-15；任务：M1-304。

## 结论与证据边界

这句话是 Renderer 对多个不同异常的统一降级说明，不能据此认定是大模型服务宕机、网络不好或 K 线不足。

用户确认截图来自另一台电脑的最新版。本机日志没有该次请求，具体客户端构建号、失败时刻、原策略和原始错误尚未取得。因此，本记录确认代码缺陷与可复现的触发路径，不把故障注入结果冒充截图那次事件的线上根因。

截图显示 SNDKUSDT、1 小时、600 根 K 线，完成文案包含“兼容分析与安全绘图”。对照 `runTradingStrategyChartRequest` 可判断，这次经历了原策略失败后的通用分析回退，随后又进入本地价格结构恢复。截图中的本地报告不能用于证明指定策略或模型已执行成功。

## 原有调用链

```text
策略请求
  → 会员/积分实时校验
  → 行情标准化、确定性策略引擎
  → 模型复核、输出规则校验（部分策略使用模型）
  → 生成执行方案、Drawing Patch
  → Renderer 落图、保存绘图、整理报告
  → 异常时尝试通用价格结构分析
  → 通用链路异常时返回本地简化报告
```

原通用链路的一个大 `catch` 覆盖了数据准备、IPC、模型返回、落图和报告整理。只要还有至少两根可用 K 线，就可能生成同样的“指定分析增强暂时不可用”说明。

## 已确认的问题与修复

| 问题 | 证据 | 本轮处理 |
|---|---|---|
| 空结果跳过复核重试 | Provider 对空文本抛出 `TRADING_ANALYSIS_MODEL_EMPTY_RESPONSE`；该异常发生在模型校验 `try` 之外 | 空结果进入原有 medium → high → max 有限复核流程，最多三次；鉴权、取消和传输错误保留独立策略 |
| 绘图失败丢弃成功分析 | 模型成功后，落图/绘图持久化异常仍进入同一外层降级分支 | 绘图单独处理，保留已验证的原报告与模型身份，返回 `drawingDeferred` 并明确说明绘图未完成 |
| 取消被当成恢复成功 | 本地降级的绘图 `catch` 不区分停止与普通绘图异常 | 所有新增绘图恢复均检查任务仍有效和取消错误，不将取消标记为成功 |
| 权益/鉴权失败被掩盖 | 主进程返回明确错误码，但 Renderer 通用降级仍可生成本地分析；外层还可能再次请求通用链路 | 权益、鉴权、套餐/积分和权限错误停止降级，显示对应原因 |
| 非数据错误被解释为 K 线不足 | `buildTradingAnalysisAvailabilityReport` 忽略传入错误，固定声称少于两根可核验 K 线 | 按真实错误类别说明失败，不再从任意异常推断 K 线数量 |
| 事后难以追溯 | 原始降级原因仅在内存中返回，最终报告保存过程没有保留该字段；部分日志仅为控制台输出 | 接入现有 `turn-diagnostics.jsonl` 及“导出故障诊断报告”，记录失败阶段、任务关联哈希、市场/周期、错误码、HTTP 状态、校验字段、复核次数与原因分类 |
| 错误信息沿调用链丢失 | App Server → Provider → IPC 会丢失 HTTP 状态；会员校验包装异常未保留 cause | 保留结构化状态与请求关联信息；权益失败保留底层原因的分类、状态和哈希 |

新诊断记录使用固定文案和字段白名单，不保存提示词、模型正文、账户数据或凭证。诊断写入失败不改变分析结果；保留原逐轮诊断功能的可移除边界。

## 已检查但不能认定为本次事件根因的因素

- **网络断流/超时：** 模型轮次已有传输恢复；理论复核使用 180 秒无活动超时，活动会续期。不是固定运行 180 秒就必然降级。内部任务创建在轮次恢复之前，创建失败仍可能导致请求失败。
- **模型输出不合规：** JSON、schemaVersion、verdict、summary 等校验失败原已有三级复核；三次失败仍会降级，这是有效结果保护。空输出以前未进入该流程，本轮已修复。
- **会员服务波动：** 意图识别与正式分析均可能执行实时会员校验；校验依赖账号服务，不能从 K 线能显示推断该依赖健康。
- **行情或规则不足：** 600 根 K 线不能保证每一种策略都有有效候选，也不能证明数据已通过标准化校验。
- **图表/会话切换与存储：** 已成功的模型请求仍可能在目标检查、画图或持久化阶段失败。新处理保留模型结果，但没有绕过绘图目标、权限或坐标校验。

本轮没有改模型、放宽输出校验、绕过会员权限、增加无限重试或修改交易算法。
