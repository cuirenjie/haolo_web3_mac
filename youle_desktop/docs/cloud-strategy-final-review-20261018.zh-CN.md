## 交付行为

Windows 的 17 个官方策略、普通盘面和持仓分析从服务端执行；客户端接收经过校验的公开报告、条件计划、绘图和提醒。官方引擎、提示词和偏好语义编译器不再进入新分发包，也没有隐藏的本地官方策略回退。通用图表指标、默认根编排和个人策略功能保留。

有效交易偏好以服务端版本为准，保留原文、字段来源和显式默认选择。第一题为左侧、右侧、自动入场，默认自动。自定义文本先编译为封闭的类型化规则，全部校验后原子保存；不支持的要求不能伪装为可执行规则。旧本地数据保留，来源不明或与云端冲突的字段由用户确认。跨设备修改使用版本校验，避免后台读取覆盖正在编辑的版本。

每次分析冻结偏好、账户依据、行情窗口、模型与协议；后续设置修改只影响新任务。报告、卡片、主图/分屏绘图、便利贴、历史和云端提醒使用同一份 EntryConditionV2 及其规范 JSON 字节哈希。条件触发只产生提醒，不表示成交或自动下单。持仓分析有独立报告和风险来源，不生成新开仓计划。

取消、断线和重启恢复使用预分配任务 ID、幂等请求、加密本地记录及服务端租约。未知付费模型结果不会自动重发；已完成步骤复用冻结检查点。Windows 与移动任务分开限流和消费，默认各 8 个在途任务，配置范围 1–64；排满返回明确错误和重试时间。此容量限制不是生产吞吐量承诺。

## 后续上线顺序及运行风险

CP01–CP04 的本地实现及各项验收已交付；CP05 的 G3 与回滚准备已完成，实际生产灰度和线上回滚未执行。新客户端应在服务端对应版本完成验收后发布，不能单独提前推送给用户。

1. 先核验生产 API、独立 Worker 和数据库各自基线，备份并应用兼容的增量 schema；不删除旧字段或历史记录。
2. 按现有平滑发布流程升级独立 Worker，保留真实心跳与任务排空。新 Worker 的协议前缀兼容旧 API。所有活跃消费者满足 `windowsservice1:` 扩展前，不允许新 Windows 任务进入；禁止删心跳伪造就绪。
3. 再升级业务 API，验证三语响应、鉴权、模型权益、持久化、取消/恢复、移动兼容和真实生产行情；保持既有零 5xx 门禁。
4. 小范围发布已扫描签名客户端，观察两条队列长度、超时、失败率、恢复/取消、模型用量与提醒延迟，再扩大范围。当前队列压力测试是受控场景，不能替代生产硬件负载测试或 SLA。
5. 回退先停止新 Windows 任务准入并排空/处理新版任务，再切换已验证兼容版本；保留冻结记录和增量 schema。旧 Worker 不得接管其不能理解的新协议任务。客户端回滚包也必须移除私有资产，不能退回含旧官方策略/提示的历史安装包。

迁移会增加对网络、服务端可用性、行情源和模型延迟的依赖，并把计算、队列和模型成本集中到服务端；受控取消、额度及隔离减轻影响，但不能消除故障。任何模型或结构判断不合格时应明确等待/失败，不用虚构计划换取表面成功。当前没有发现尚未处理的已知实现缺陷；这不构成对所有行情、网络故障和未来模型行为零错误的承诺。
