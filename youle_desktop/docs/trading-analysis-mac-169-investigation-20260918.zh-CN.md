## 9 月 18 日诊断结论与原始证据

主要阻断点是 **Mac 客户端读取长期记忆/交易偏好时，系统安全存储不可用**。正式策略和通用分析都把该读取作为前置步骤，异常直接中断流程；通用重试再次遇到同一异常，最终显示截图中的本地价格结构恢复报告。

用户提供的诊断报告有 20 条失败事件，按 `analysisHash` 关联为 6 组，不能解释为 20 个独立问题：18 条、5 组为 `SECURE_STORAGE_UNAVAILABLE`；另 2 条、1 组是当前行情快照刷新未完成。两种错误的原始文案均已通过生产诊断算法与 169 对应源码精确匹配。账号模型请求被全部拒绝、余额耗尽或模型空回答不是这些事件显示的阻断点。

尚不能由报告确定 macOS 安全存储为何不可用（钥匙串状态、授权或应用身份等需要设备侧信息），也不能据此认定已存记忆损坏或 API Key 解密失败。当前仅完成排查，无业务代码修复、生产变更或现场恢复声明。

## 客户端定位与放大机制

- `src/main/personal-context/memory-store.mjs:194` 在账户存在 `encryptedProfile` 时检查 `safeStorage` 是否可用，不可用则在实际解密之前抛出主错误。不存在已存记忆的账户会先返回空 profile，因此“部分用户正常、这位用户持续失败”与这条路径相容；报告不包含具体记忆内容，也不能证明是某项交易偏好值错误。
- `src/main/main.mjs:15158` 的 `tradingStrategyParamsWithPersonalRisk` 没有隔离长期记忆读取失败。`runTradingStrategyRequest` 和 `tradingAnalysis:runGeneral` 都依赖它，所以威科夫失败后，改走通用分析仍会失败。由于还未进入模型分析，模型切换/重试无法解决这个前置异常。
- `src/main/trading-analysis/failure.mjs` 没有针对长期记忆安全存储和上述行情刷新文案的分类，均落为 `analysis`，固定说明“分析流程未能完成”，并允许本地恢复。用户因此看不到真正的阻断原因。
- `src/renderer/main.ts:31783` 的策略异常处理调用通用分析；`src/renderer/trading-expert-market.ts` 的 `runGeneralConversation` 再捕获通用准备异常，在还有可用 K 线时调用 `buildRecoverableTradingAnalysis`。`src/renderer/trading-analysis-recovery.ts` 生成截图所示报告。支撑、压力及画线来自本地恢复，不能证明原威科夫策略或模型复核成功。
- 普通模型上下文的 `buildPersonalTradingPreferenceDeveloperInstructions` 已单独捕获长期记忆读取错误并返回空偏好说明。这解释了为什么后台仍可能看到有输出的请求，但不能单凭用量记录认定该用户普通聊天已通过现场验收。
- 当前机器两份会话均非反馈账号。本机同日 ONDOUSDT 的威科夫数据不足记录不能用来解释该用户 ETHUSDT 的事件。

## 待处理范围与建议

[Electron 官方 safeStorage 文档](https://www.electronjs.org/docs/latest/api/safe-storage) 说明 macOS 使用 Keychain，`isEncryptionAvailable()` 取决于钥匙串是否可用，并强调应用代码签名身份一致性。本机 169 发布记录为 ad-hoc 签名，缺少 Developer ID 签名与公证；这使安装/更新后的身份授权值得检查，但不是“169 签名导致本用户故障”的证据。报告没有原生 Keychain 状态或授权结果，不能确定锁定、拒绝授权或签名变化中的哪一个条件成立。

- 客户端应为长期记忆读取失败增加明确分类和可操作提示，并避免同一前置错误触发无效的策略 → 通用重试；行情新鲜度拒绝应有独立错误码，保留阻止旧 K 线分析的规则。
- 如设计记忆不可用时仍提供只读盘面分析，必须显式标记个性化风险约束不可读并限定输出能力，不能悄悄把“读取失败”当作“用户无硬约束”，继而输出依赖个人风险约束的执行计划。应保持加密要求及原有文件，不用明文、清空记忆或删除钥匙串绕过。
- 设备侧下一步是核对故障时安全存储可用性、应用身份和钥匙串授权状态，并在恢复后复测一次策略与通用分析。该步骤尚未进行，不宣称本轮已让用户恢复使用。

M1-304 保持进行中，原有其他设备现场验收依赖不变。本轮交付是已定位、可复核的排查结论；没有提交、推送、打包、发布、账号变更或付费模型调用。
