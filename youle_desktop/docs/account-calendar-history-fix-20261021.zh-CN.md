# Windows 账户日历、当前委托与仓位历史修复

2026-10-21，任务 `01a15d84-82b9-7d22-bb5c-bb71a14fc69e`。

用户要求直接修复并实际验证，且明确移动端当前正常。本次不修改移动端源码，Windows 复用已上线的移动账户明细接口。共享后端仅新增日历接口及限制 Windows 可选今日收益查询的等待时间。

## 根因与实现

- Windows 共享账户摘要将 `openOrders`、`positionHistory` 固定填成空数组，页面把“未读取”当成“没有记录”。新增独立明细读取链路：账户页 → preload → 经过身份验证的主进程 IPC → `/api/mobile/v1/account-connections/{id}/details`。对应 `openOrders` 和 `positionHistory`，沿用原分页游标。
- 远端绑定被收益日历 loader 的 `remoteOnly` 条件排除，主进程日历也只读取本地凭据。现在有共享凭据的远端绑定通过新增的 `profit-calendar?month=YYYY-MM&timeZone=...` 接口读取归档；本地独立绑定保留原链路。
- 含 `pnlTimeZone` 的摘要请求可能等待收益历史额度约 65 秒，而客户端 20 秒超时。后端为这项可选收益读取设置 2 秒上限并采用已有的立即额度准入，失败时保留资产和持仓，不伪造收益零值。移动端不带此可选参数的调用保持原样。
- 明细和日历不再依赖摘要成功。增加加载、失败、部分覆盖、旧归档和真实空集合状态；失败保留成功记录，切换绑定及重新绑定清除旧缓存，迟到响应不能覆盖新账户。
- 日历按时区日界和完整归档覆盖聚合 `REALIZED_PNL`，手续费只表示交易活动，保持 Windows 原有已实现盈亏口径。缺失日期不冒充“无交易”，不完整月份不计算总收益。
