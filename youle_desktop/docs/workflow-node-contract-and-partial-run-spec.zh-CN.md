# Haolo 可编辑画布节点契约与局部运行规范

> 状态：产品与架构决策基线
> 决策日期：2026-08-02
> 适用范围：Haolo 桌面端可编辑工作流画布、模型节点、Haolo/Codex 子 Agent 节点、嵌套画布节点，以及未来通过同一执行边界接入的外部 Agent 节点。
> 实现说明：本文定义必须遵守的目标行为，不表示所有能力已经完成。实现时不得用临时正则、Renderer 私有状态或隐式全局上下文替代本文的契约、预检和数据路由。

## 1. 目标

让不懂工作流编程的用户只通过自然语言定义节点的输入、任务和输出，由 Haolo 将其一次性编译为可执行契约，并让画布连线、总输入框、节点固定附件、执行器和统一结果信封按照同一份契约工作。

核心关系是：

```text
用户自然语言
  -> Haolo 语义编译
  -> 节点输入/任务/输出契约
  -> 画布传播与发送前预检
  -> 确定性执行
  -> 唯一终点的 ExecutionResult
```

Haolo/Codex 负责理解和编译；代码负责强制校验和路由。发送时不得重新依赖模型临场理解同一个节点的输入输出约束。

## 2. 不可破坏的规则

1. 节点提示词始终包含不可删除的 `输入：`、`任务：`、`输出：` 三部分。
2. 输入和输出只向用户展示四种顶层类型：文字、图片、视频、文件；内部必须保留语义名称、数量范围、必选性、扩展名/MIME 和稳定槽位 ID。
3. 下游节点的输入完全由画布连线和上游输出生成，用户不可修改。
4. 节点固定附件永远是额外输入，不替代、不抵扣任何运行输入或上游输入。
5. 总输入框只向与它直接连接的本次一级节点注入数据，绝不越级给下游节点补输入。
6. 工作流只能是有向无环图；会形成环路的连线必须拒绝。
7. 汇聚节点只允许“等待全部上游成功”，不提供其他汇聚策略。
8. 从本次运行入口可达的子图必须且只能有一个终点节点。
9. 一次运行只产生一个最终 `ExecutionResult`；该信封内部可以包含文字、结构化数据和多个文件/媒体产物。
10. 节点、连线、契约和输入提示的语义修改必须原子保存到新草稿；历史运行和冻结版本不可被覆盖。
11. 不依赖隐式全局共享上下文，不偷用历史运行结果，也不让固定附件暗中替代缺失依赖。

## 3. 核心术语

### 3.1 节点稳定身份

每个节点内部使用永久 UUID。用户可见的 A、B、C、D 等编号只用于展示和来源说明：

- 创建后固定；
- 移动画布位置不改变；
- 删除节点后不重新排列已有节点；
- 同一画布版本内不复用被删除编号；
- 提示词中的“来自节点 A”实际绑定 UUID，不依赖名称文本查找。

### 3.2 本次一级节点

“一级节点”是相对于本次运行定义的：凡与总输入框直接连线的节点，都是本次一级节点。它不一定是原画布最顶部的节点。

### 3.3 输入槽位

每份可路由输入都对应稳定 `slotId`。概念字段如下：

```text
slotId
type                  text | image | video | file
semanticName          产品图、Logo、需求文档等
minCount / maxCount
required
accept                扩展名或 MIME 约束
source.kind           run_input | upstream_output | fixed_attachment
source.nodeId
source.outputSlotId
displayOrder
```

用户界面保持简单，不直接展示这些底层字段。

## 4. 节点提示词

### 4.1 固定结构

新增节点时自动生成：

```text
输入：

任务：

输出：
```

三个标题、顺序和系统生成的来源标注不可删除。实现上应使用三个受控区域或等价的结构化编辑器，不能依赖用户在普通自由文本框中保留标题。

### 4.2 入口节点

没有工作流上游连线的节点，其输入由用户填写并在保存时编译。示例：

```text
输入：一张产品图、一个 txt 文档
任务：描述图片，并把描述写入 txt 文档
输出：原样保留的产品图、处理后的 txt 文档
```

### 4.3 下游节点

只要节点存在工作流上游连线，它的 `输入：` 就由系统根据全部上游输出生成并设为只读，例如：

```text
输入：
图片1（来自节点 A）
文件1（来自节点 A）
文字1（来自节点 B）
```

用户若要改变这些输入，只能修改上游节点的输出或画布连线。

不保存 `declaredInput` 与 `resolvedInput` 两份影子数据。节点始终只有一份当前有效的输入契约：

- 接上游后，当前输入被连线派生结果替换；
- 上游全部删除后，节点输入变为“待定义”，用户需要重新填写并保存；
- 系统不会恢复节点过去作为入口时的旧输入。

### 4.4 固定附件在提示词中的呈现

通过节点编辑器“＋”添加的图片、视频或文件是节点固定附件。它们作为额外输入追加到提示词：

```text
输入：
图片1（来自节点 A）
文件1（节点固定附件：《参考资料》.pdf）
文件2（节点固定附件：术语表.txt）
```

添加、删除或失效时重新生成固定附件部分，但不改变动态输入数量。

## 5. Haolo 语义编译

### 5.1 编译时机

用户点击“保存修改”后，Haolo/Codex 对节点的 `输入/任务/输出` 和固定附件做一次语义编译，生成当前节点唯一有效的：

```text
InputContract
TaskDefinition
OutputContract
```

不得用关键词正则代替语义理解。编译结果必须经过结构校验后保存，运行时只读取冻结契约。

### 5.2 歧义处理

“一些图片”“几个文件”“合适的视频”等无法确定数量或类型的表达，不得由系统猜测。Haolo 应阻止保存，指出具体歧义并要求用户补充。

### 5.3 类型与数量

四种顶层类型之下必须支持：

- 精确数量，例如一张图片；
- 数量范围，例如至少两张、最多三张；
- 必选与可选；
- 文件扩展名，例如 `.txt`、`.pdf`；
- MIME 类型；
- 语义名称，例如产品图、Logo、合同正文。

### 5.4 执行者能力预检

保存和冻结前必须确认当前执行者能够：

- 读取声明的输入类型；
- 接收对应的图片、视频或文件参数；
- 实际产生声明的输出；
- 在需要时修改文件、运行命令、操作应用或发布。

外部模型只有分析能力时，不得假装能够创建或修改本地文件。能力不匹配时阻止保存或要求切换到具备相应能力的 Haolo/Codex 子 Agent。

## 6. 输入槽位编号与复用

### 6.1 默认共享

多个并联入口要求兼容的提示词、文件、图片或视频时，默认认为它们使用同一份运行输入。只要节点定义没有明确要求“不同”“分别”“各自独立”等资源身份，就只生成一个槽位；用户填写或上传一次，运行时把同一资源引用分发给所有直接入口节点。

该规则优先于按节点机械拆槽，不能因为两个节点各自写了一次“提示词”就显示两个提示词输入框。语义编译器应比较并联入口；即使名称略有不同，只要没有明确的资源差异要求，也要绑定到已有槽位。

### 6.2 显式区分

只有节点定义明确要求不同资源时才拆分槽位，例如“节点 A 使用产品图、节点 B 使用另一张 Logo”“两个节点分别使用不同提示词”。独立资源必须写入稳定的差异标识；同类型、同名但带不同差异标识的槽位仍保持分开。

### 6.3 稳定排序

总输入框中的槽位编号按以下顺序生成：

1. 直接入口节点的固定展示编号 A、B、C……；
2. 同一节点内输入在提示词中的出现顺序；
3. 默认共享或显式复用的同一 `slotId` 只出现一次；
4. 固定附件不参与总输入框编号。

不能按画布坐标、拖动后的视觉位置或连线创建时间排序。

## 7. 三类输入来源

### 7.1 一级节点

```text
一级节点输入 = 总输入框运行输入 + 当前节点固定附件
```

### 7.2 非一级节点

```text
非一级节点输入 = 全部上游节点输出 + 当前节点固定附件
```

### 7.3 固定附件永远附加

固定附件永远不能：

- 替代总输入框要求的运行输入；
- 替代上游节点应该产生的输出；
- 减少 `minCount` 或 `maxCount` 所要求的运行材料；
- 补齐局部运行中缺失的旁路上游；
- 自动传递给下游节点。

只有节点输出契约明确要求原样传递固定附件时，它才会作为输出资源进入下游。

固定附件应保存稳定 `ArtifactRef`，冻结版本不得依赖随时会消失的临时路径。发送前发现附件丢失、无法读取或内容身份不匹配时必须失败关闭。

## 8. 画布连线与契约传播

### 8.1 连线是输入来源

建立、删除或改接连线后，系统重新计算受影响节点及其下游的输入契约、提示词来源标注和预检状态。

### 8.2 下游输入只读

下游输入由所有直接上游的输出槽位组成，不允许用户手工增删或改写。输出类型、数量或来源发生变化时，下游输入必须同步变化。

### 8.3 只等待全部上游

汇聚节点必须等待全部上游成功后才能执行。前端删除“汇聚条件”选择器及相关选项；底层策略固定为等价于：

```text
joinPolicy = all_upstreams_succeeded
```

不支持“任一上游完成”“达到最少数量”或其他候选策略，也不能保留一个看似可选、实际被忽略的控件。

### 8.4 禁止环路

创建或改接连线时立即检测环路。会形成环路时拒绝操作并提示：

> 工作流不能形成循环连接

冻结和发送前仍需在主进程重复校验，不能只依赖前端。

## 9. 总输入框与局部运行

### 9.1 运行入口

总输入框可以连接一个或多个节点。直接连接节点成为本次一级节点，当前运行只执行这些入口可达的下游子图。

入口节点原有的工作流上游不会在本次运行中执行；总输入框根据该节点当前输入契约提供等价的测试数据。这个运行边界不会改写节点定义或历史运行。

### 9.2 不允许越级注入

总输入框材料只进入直接连接节点。它不能直接进入第二级或更下游节点，也不能在运行到汇聚点时临时补充缺失数据。

如果可达下游节点依赖一个不在本次运行范围内的上游输出，发送前阻止运行并明确指出：

> 当前运行链路缺少节点 B 的输出

用户必须把缺失上游纳入运行入口并建立完整可达链路，或者调整画布连线；不得通过总输入框越级补齐。

### 9.3 输入 UI

总输入框根据所有直接入口的运行输入槽位动态生成简洁的命名输入项：

- 单个文字槽位直接使用主输入框；
- 多个文字槽位在主输入框上方显示独立命名输入项；
- 图片、视频和文件按槽位显示待上传、已上传、替换和删除状态；
- 未明确要求不同资源的兼容槽位默认合并，只填写或上传一次；
- 明确要求不同资源的槽位分别编号和展示；
- 默认共享或显式共享的同一槽位只上传一次。

输入提示和发送校验必须读取同一份冻结契约，不能分别拼接两套文案和逻辑。

### 9.4 严格校验

发送前按槽位严格校验：

- 少于最小数量：失败；
- 多于最大数量：失败；
- 类型、扩展名或 MIME 不符：失败；
- 必选槽位缺失：失败；
- 没有对应槽位的额外文字、图片、视频或文件：失败。

例如要求一张图片和一个 txt 文档时，任何少传、多传或错传都禁止发送，并提示：

> 请上传一张图片和一个 txt 文档

### 9.5 多入口重叠保护

若多个直接入口之间存在祖先/后代关系，同一节点可能同时收到手工测试输入和另一入口的运行输出。预检应拒绝这种重叠入口，要求用户只保留互不为上下游的入口连接，避免节点重复执行或输入来源歧义。

## 10. 唯一结果约束

从本次所有一级节点沿连线遍历得到可执行子图，并统计其中没有可达下游的终点节点：

- 恰好一个终点：允许运行；
- 两个或更多终点：禁止运行；
- 没有终点，例如存在闭环：禁止运行。

多条并行分支可以存在，但必须最终汇聚到同一个终点。多个独立末端存在时，点击发送不启动任何节点并提示：

> 运行链路只能输出一个结果

“一个结果”指一个终点节点产生的一份统一 `ExecutionResult`，不是只允许一个文件。该信封可以同时包含文字、数据、图片、视频和多个文件。

不在本次入口可达范围内的孤立节点允许保留，不参与本次执行、输入校验或终点统计。

## 11. 执行与失败传播

1. 主进程对冻结 Spec 和本次运行入口重复进行结构、契约、能力、附件和唯一出口预检。
2. 节点按 DAG 拓扑顺序调度。
3. 一级节点接收总输入框路由的槽位和自身固定附件。
4. 非一级节点只在全部上游成功并交付合格输出后执行。
5. 任一必要上游失败、缺失或输出不合约时，下游不执行，整次运行以真实失败状态结束。
6. 失败不自动回滚；展示实际状态和可执行补偿方案。
7. 终验失败不自动重新规划或重跑，成功就是成功，失败就是失败。

## 12. 输出、产物与数据血缘

每个节点继续通过统一 `ExecutionResult` 返回：

```text
status
text
data
artifacts[]
evidence[]
error
usage
```

当输出要求“与输入相同的图片/文件”时，允许不经过模型重新输出，直接把原始 `ArtifactRef` 传递到结果信封。必须保留：

- 原始资源 ID；
- 来源节点和输入槽位；
- 当前输出槽位；
- 是否原样传递；
- 是否为新生成或修改后的资源；
- 内容哈希和可审计引用。

固定附件同样只有在输出契约明确要求时才能进入输出。禁止复制二进制后冒充新产物，也禁止模型伪造不存在的文件或媒体链接。

## 13. 嵌套画布

历史画布作为 `nested_workflow` 节点加入父画布时：

- 绑定确切 `specId + version + contentHash`；
- 不自动跟随历史画布的最新修改；
- 对父画布暴露一份固定输入契约和一份固定输出契约；
- 固定输入契约必须由冻结子画布的总输入框调用契约计算，继续遵守并行入口默认共享同类输入、只有明确声明不同资源时才拆分槽位的规则；
- 固定输出契约必须等于冻结子画布唯一最终节点的结构化输出契约，父画布不得将其改写为“自动”或“待定义”；
- 通用下游输入推导不得覆盖嵌套画布的固定输入契约；父画布重新保存、冻结和运行前都必须从被引用版本重新校准边界契约；
- 添加或连接前必须同时校验类型、数量范围和文件/MIME 接受范围。所有直接上游输出必须完整满足固定输入，固定输出也必须满足已有下游节点的输入；任一方向不兼容时整次添加或连接不落盘；
- 例如，子画布要求文字输入时不能连接输出 PDF 的上游；子画布最终输出 Word 文档时不能连接只接受文字的下游；`.docx` 与对应 Word MIME 可作为同一文件族匹配；
- 从接收父节点输入开始完整执行冻结子画布；
- 嵌套执行必须按固定槽位路由父节点文字结果和附件，不能只把路径拼进提示词后绕过输入预检；
- 通过一个统一结果信封返回父画布；
- 递归引用、子画布多终点或契约不完整时预检失败。

## 14. 草稿、冻结与原子保存

节点保存可能同时改变节点契约、下游输入、总输入框提示、上传校验、能力匹配、唯一出口和可执行范围，因此必须作为一次原子操作：

1. 在内存中生成候选 `WorkflowRevisionDraft`；
2. 运行语义编译和整图预检；
3. 全部成功后一次提交新草稿版本；
4. 任一步失败则不写入任何部分变化；
5. 纯坐标和缩放变化仍只写 `WorkflowLayout`；
6. 执行前冻结为不可变 `WorkflowSpec`；
7. 历史运行、正在运行的实例和定时任务绑定的冻结版本保持不变。

## 15. 前端实施要求

### 15.1 节点编辑器

- 固定显示不可删除的输入、任务、输出区域；
- 下游输入区域只读；
- 支持添加和删除固定附件；
- 支持选择具备所需能力的外部模型或 Haolo/Codex 子 Agent；
- 删除“汇聚条件”控件及其所有前端分支；
- 不恢复输出格式下拉框、输出要求输入框或结构化模板；
- 输出形态继续由 Haolo 根据节点提示词编译。

### 15.2 总输入框

- 根据当前直接入口契约实时显示命名槽位；
- 上传区明确标注图片1、图片2、文件1等绑定关系；
- 支持替换单个槽位，不依赖上传顺序猜测语义；
- 发送按钮在预检不通过时不得启动运行；
- 错误提示必须指出缺少、多余或错误的具体槽位。

### 15.3 主题与交互状态

所有新增或调整的节点编辑、槽位卡片、附件卡片、错误提示和禁用发送状态必须同时覆盖浅色与深色主题，以及默认、悬停、选中、聚焦、加载、失败和禁用状态。

## 16. 主要预检错误

建议稳定错误码与用户文案分离，至少覆盖：

| 场景 | 用户文案示例 |
|---|---|
| 输入语义有歧义 | 无法确定“几张图片”，请明确数量 |
| 形成环路 | 工作流不能形成循环连接 |
| 缺少旁路上游 | 当前运行链路缺少节点 B 的输出 |
| 多个终点 | 运行链路只能输出一个结果 |
| 输入不足或类型错误 | 请上传一张图片和一个 txt 文档 |
| 输入超量 | 图片1只允许上传一张图片 |
| 固定附件失效 | 节点 C 的固定附件“参考资料.pdf”无法读取 |
| 执行者能力不匹配 | 当前模型不能生成或修改本地文件，请切换执行者 |
| 嵌套画布版本失效 | 所选子画布版本不存在或已损坏 |
| 嵌套画布输入不兼容 | 上游输出不符合历史画布的固定输入要求 |
| 嵌套画布输出不兼容 | 历史画布的固定输出不符合下游节点的输入要求 |

## 17. 验收场景

实现至少应通过以下端到端场景：

1. 单入口节点要求图片和 txt，提示、上传槽位、严格数量校验与发送一致。
2. 两个并联入口都要求提示词但没有明确要求不同提示词，只显示一个主提示词输入框，并把同一值路由到两个节点。
3. 两个并联入口分别要求兼容的文件、图片或视频但没有明确要求不同资源，每种输入只生成一个共享槽位。
4. 两个并联入口明确要求不同图片，显示图片1和图片2并分别路由。
5. 节点固定添加 PDF 后，动态输入要求不减少，节点实际收到动态输入加固定附件。
6. 修改上游输出后，下游只读输入和提示词原子更新。
7. 删除全部上游后，节点输入进入待定义状态，不恢复旧入口输入。
8. 总输入框连接中间节点，只向该节点注入，不越级给下游补数据。
9. 局部子图存在缺失旁路上游时，发送前失败且不运行任何节点。
10. 并行分支最终汇聚为一个终点时允许运行。
11. 可达子图存在两个终点时提示“运行链路只能输出一个结果”。
12. 尝试创建环路时前端拒绝，主进程预检也拒绝伪造数据。
13. 原图原样输出时复用 ArtifactRef，并完整保留数据血缘。
14. 外部模型无法写文件时，保存或冻结前阻止不可能的执行计划。
15. 嵌套画布锁定版本并只返回一个结果信封。
16. 浅色与深色主题中的所有槽位、附件、错误和禁用状态可读且一致。

## 18. 不纳入本规范的能力

- 任意上游完成即可运行；
- 基于最少通过数的汇聚；
- 循环工作流；
- 总输入框越级向下游注入材料；
- 固定附件抵扣动态输入；
- 多终点结果自动拼接；
- 发送时再次让模型猜测输入输出契约；
- 通过隐式历史上下文补齐当前运行数据；
- 多人实时共同拖拽编辑。
