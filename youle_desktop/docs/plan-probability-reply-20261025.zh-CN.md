# M1-463 计划卡片下方的模型概率回复

2026-10-25：本地源码和隔离验证完成；未提交、推送、部署或发布安装包。

## 展示规则

- 左侧、右侧策略、指标及纯文字通用分析生成有效计划后，在对应计划卡片及操作栏下方展示独立模型评估；当前及历史计划共用这一顺序。
- 按用户截图删除“100% − 止损概率 = 盈利概率”整行，简体中文、繁体中文、英文和韩语同步生效；保留盈利概率数值与评估说明。
- 盈利概率 = 100% − 止损概率，以两位小数固定保存。严格大于 50% 才显示；恰好 50%、更低、数据不足或评估失败都不显示追加回复，卡片及其操作保持原样。
- 不随机调整概率，不把模型结构置信度用作胜率，不变更任何价格、仓位或提醒条件。
- 标明“模型估算”和“未经历史回测校准”。二元口径为：入场触发后、有效期内至少到达第1止盈或止损之一，估计第1止盈先到的概率；未触发、未退出和分批退出的最终净盈亏不在口径内。

## 实现

规范后端 `haolo_front_web3/youle_mas-dev/backend/app/mobile/plan_probability.py` 在最终计划投影之后、`private_analysis` 持久化之前评估。输入只含冻结计划、策略证据及最近最多120根已收盘K线，不足60根不调用模型。单次评估沿用现有无工具、带计费和持久化检查点的模型通道，最多30秒；不把展示阈值放入提示词。

模型只返回止损概率、证据引用与简短公开说明。Host 校验数值、情景索引、证据与语言，计算补集后应用阈值；不输出原始模型 JSON。取消、授权撤销和冻结输入变更继续向外传播，模型失败只影响可选回复。

结果通过 `analysisPlan.profitProbability` 随原始报告、云端结果哈希和已保存计划的 `desktopReceipt` 保存。客户端 `plan-probability-view.mjs` 再次核对计划ID、方向、入场、止损、目标、条件哈希、时间窗口和补集，错误可选字段被丢弃而不影响卡片。模型正文按纯文本转义。历史重开只读取原结果，旧报告不补算；输出在整轮完成后显示。

客户端卡片和便利贴的原字段保持兼容；模型评估显示在对应聊天计划卡片及操作栏之后。简体中文、繁体中文、英文和韩语共用数据、分别显示本地化标题及说明，亮暗主题使用既有语义变量。
