## 排查证据与修复

1. 开发日志 `.dev-account-verify-20261021-170023.err.log` 记录 `HTTP 429 / BINANCE_UNAVAILABLE / retryAfterMs=13000`。主进程之前只封装 `BINANCE_RATE_LIMITED`，其他错误直接抛出；Electron 丢失附加属性，前端看不到服务端等待时间。状态、摘要、明细、日历现统一传递公开错误属性，不传原始响应或凭据。
2. 共享摘要忽略本地 summary/live/full 模式，但手动刷新依然走最多三次的渐进加载。共享绑定现只请求一次摘要并完成原有执行计划核对；本地独立绑定保留渐进流程。
3. 多个读取路径重复获取绑定并发出同一请求。新增仅供账户 GET 使用的协调器：合并同一身份、相同路径的并发读取；绑定列表有 750ms 短缓存；摘要和交易数据不使用成功缓存代替新读取。短暂网络错误、超时或可恢复 5xx 最多增加一次带随机间隔的重试。429/418 或带 Retry-After 的响应进入对应数据集的等待期。2026-10-21 追加修正：摘要、委托、历史、日历分别分组，摘要的限流不能阻止服务端返回已核验归档；服务端仍统一执行真实交易所 IP 总额与封禁等待。写请求不自动重放。绑定写入前后清除等待请求与短缓存；身份切换不复用旧状态。
4. 明细失败原来没有独立退避，日历原来成功加载后永久跳过同月刷新，且摘要缺失时后台更新会停止。现在明细失败保留已有记录并退避；日历每 30 秒可更新，失败遵守等待时间；共享账户明细/日历无需摘要成功也可继续更新。明确的无效凭据继续停止重试并要求重新绑定。
5. 上游代理非 JSON 的 502 原来丢失 HTTP 状态，无法按可恢复故障处理；现在保留状态用于账户 GET 的有限重试。

今日盈亏与连接状态分别核对：服务端的可选收入历史读取有独立限额和 2 秒预算，缺失该字段不等于资产连接失败。本次真实读取已返回 `pnlStatus=available`。收益历史和日历当次仍返回 `stale` 归档；删除展示提示不改变其内部状态或时间戳，也不代表归档已实时同步。
