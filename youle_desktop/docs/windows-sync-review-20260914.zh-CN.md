## R1 / P2：线路探测的局部 HTTP 故障阻断全部账号业务

位置：`src/main/haolo-service-fetch.mjs:63–65,96–103`。

冷启动或 60 秒线路缓存到期后，所有规范域名 `/api/` 请求都必须先成功读取 `/api/auth/config`。该探测返回 429/503 时被转换成没有网络错误码的普通 Error，`selectRoute` 在第 99 行立即抛出，既不验证备用入口，也不进入第 103 行的失败冷却。

因此，即使用户资料、联系人、更新等业务端点本身正常，且 `www.haolo.com` 的配置端点也正常，这些业务请求仍会全部在发送之前失败。连续业务调用还会反复撞击同一个失败或受限的探测端点。这个行为是本轮新增的前置依赖；既有业务响应 401/429/500 不做重放的安全规则不能直接替代匿名探测的恢复策略。

隔离复现分别让主域配置返回 429 和 503，其余端点及备用域配置均返回 200。两组均观察到：三个业务调用全部失败、备用探测零次、主域配置被连续探测三次；直接调用业务端点得到 200。没有发送真实账号请求。

建议区分探测的暂时 HTTP 故障、证书错误和服务身份不匹配。503 等探测故障应允许按策略验证备用入口；429 应遵守 Retry-After/冷却，避免把探针限流放大为全客户端故障。可以考虑独立健康探针或对已验证线路进行有界复用，继续保持业务写请求不重放、证书与服务身份校验。

## R2 / P2：握手前旧连接失败会使新的健康地址失效

位置：`src/main/trading-market-data-hub.mjs:258–259`；同类路径为 `src/main/binance-account/private-proxy-fetch.mjs:204–205`。失效语义见 `src/main/gateway-route-lookup.mjs:178–192`。

WebSocket 只有在升级成功后才设置 `socket._socket`；DNS/TCP/TLS/HTTP 升级阶段失败时，第 259 行传入的地址为 undefined。私有代理的外层 TLS 失败路径则始终只传 hostname。`lookup.invalidate` 在没有地址时会使用当前缓存地址，并无条件删除当前缓存。

当旧连接使用 A，随后缓存到期或另一请求使选路切到健康 B，旧 A 的迟到失败会错误地把 B 加入故障暂缓列表并删除 B 的缓存。后续请求重新选路，可能重新选择仍有问题的 A，破坏本轮期望的故障恢复与迟到失败隔离；影响公共实时行情及私有只读账户通道。

复现覆盖两条生产调用路径：

1. 私有代理使用隔离 TLS fixture，让 A 的 TLS 错误晚于 B 的缓存建立到达，实际失效参数只有 hostname，下一次选路回到 A。
2. `TradingMarketDataHub` 使用当前安装的真实 `ws` 和仅监听本机的 TCP 服务，连接成功后不完成升级；确认 `_req.socket.remoteAddress` 为 A、`_socket` 为 null。在缓存切到 B 后断开 A，同样观察到 undefined 地址失效及重新选择 A。

建议在每次连接的 DNS/选路完成时保存它使用的地址或选路代次，并用于 TLS/升级前失败归因；无法确定失败地址时，不应把当前缓存中的另一个地址推断成失败地址。仅在 close 时读取 `_req` 也不够稳妥，因为 ws 错误处理可能已清空它。
