## 客户端修改

- 仅对已持久化任务的状态 GET 遇到可重试 HTTP 429 做退避；初始 1 秒、指数递增，基础上限 15 秒，并加入 0–25% 正向抖动。尊重较长的 `Retry-After`，等待受原查询总期限约束。
- 同一 run ID 持续查询；不重新提交模型任务、不取消云端任务、不把本地持久化状态改成失败。进度读取成功后重置连续退避。
- 原查询期限默认仍为十分钟；耗尽后返回 `CLOUD_RUN_PENDING`，保留可恢复记录。prepared 状态的恢复检查同样可承受 429；恢复整个检查共享同一总期限。
- 自动退避恢复发生在本轮查询期限内。超期记录可经既有运行时 resume 接口恢复，已用新运行时实例验证；本次没有新增重启后自动接续或用户可点击的恢复入口，不把保留记录等同于无限后台查询。
- 简中、英文、繁中提示均明确“原任务结果尚未确认”，不再声称未生成计划或要求重新运行。策略会话的该终态使用 pending 进度；最终结果仍需通过任务、市场、偏好和输出合同校验。
- 取消、账号切换、鉴权拒绝、服务端失败终态、错误结果上下文保持原有边界。新建任务 POST 不进入自动重试。
