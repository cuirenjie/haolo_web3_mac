# Binance 私有通道用量上报导致账户超时的修复

2026-10-26。用户先要求只读排查另一台电脑的待发布 0.1.181 绑定超时，随后授权修复已复现的缺陷。本次完成本地源码与回归；未提交、打包、发布或修改生产服务。

## 已确认的缺陷

`BinancePrivateProxyTransport.fetch()` 已取得完整 Binance 响应，却仍等待 `usageReporter` 返回。账户请求的 12 秒执行期限因此包含后续用量上报。上报本身也有 12 秒控制期限，从更晚的时刻开始；上报卡住时，账户期限先到，成功响应被转换为 `BINANCE_TIMEOUT`。

排查中用实际账户服务、governor、路由器、私有传输及 gateway client 组合复现：正常模拟绑定 72 ms；仅将用量上报改为停滞，约 12,003 ms 后失败，已收到一个 Binance 响应，验证码／保存钩子均未执行。凭据和交易所数据全部为合成值，没有真实绑定或交易写入。

新增回归在原代码上稳定失败：保持用量 HTTP 响应体不结束，完整绑定无法及时返回。修复后保持同一故障，绑定仍完成，背景上报保留独立生命周期。

## 修复方式

- 完整 Binance 响应立即返回账户层，用量回报在后台执行。同步抛错、异步拒绝和超时均不能覆盖原账户结果。
- 回报一次只运行一个，最多排队 64 条，避免占满许可接口共用的连接池。溢出时优先移除普通旧回报，418／429 冷却回报优先；每条从入队起最多保留 12 秒，过期丢弃，不重放一次性回执。
- 回报使用独立 AbortSignal；完成读取后的调用方取消不撤销回报。关闭传输／切换登录态会中止活动回报并清空队列。主进程和诊断脚本均将信号传到实际 gateway client。
- 服务器 `issuePermit` 在签发前已经预扣权重。现有许可、配额、冷却与读取权限校验不变，丢弃失败／过期回报不会退还已扣额度。后台回报仍尽力提升观测权重与冷却信息；它不是免配额路径。
- 真实 Binance 超时、认证错误、CONNECT 拒绝和限流仍原样处理，不将失败伪装成绑定成功。未新增用户界面或账户写入能力。
- 同步简中、英文、繁中客服知识，状态为待发布；生成运行时合同摘要，不增加客服动作。

## 现场与交付边界

此前比对的 181 包内 8 个关键模块均包含旧网络修复，本机物理网卡的国内备用通道探测通过。服务器较早的鉴权超时不对应截图时刻；截图附近存在取得许可但缺少后续隧道记录的请求，尚不能确认属于故障电脑。因此，本次修复的是已独立复现的缺陷，不代表已确认或验收另一台电脑那一次故障的全部原因。

现有已签名的 0.1.181 安装器及其发布回执保持原状，**不包含本轮源码修复**。后续须重新构建、签名及验收后交付；本次没有上传更新系统或重启共用开发进程。
