# M1-433：左右侧条件计划与 AI 绘制过程修复

日期：2026-10-22。状态：源码与隔离验收完成；未提交、推送、部署或发布安装包。

## 问题与原因

1. 原链路将“当前没有通过策略／模型／风险校验的可执行计划”与“不展示计划卡”绑定。左侧的既有正式条件计划也必须通过真实候选和风险复核，因此等待、数据不足或风险不合格时仍可能没有卡片。
2. Windows 新右侧任务仍走 `right-legacy-v1`，等待时的旧补偿路径仅覆盖裸 K；其他策略无法统一使用 entry-v2 的右侧条件计划与结果投影。
3. 自动模式包含先右侧、再尝试左侧的选择分支，用户本次要求移除。
4. `prefers-reduced-motion: reduce` 将 AI 绘图全部动画时长设为 0。多个对象在浏览器下一次绘制前完成提交，形成整批出现。代码及模拟该系统偏好的真实 Edge 均可复现；未取得反馈用户电脑的现场日志，因此不宣称已排除其所有环境因素。

## 完成行为

- 新交易偏好只有左侧、右侧；移除自动选项及说明、新请求自动模式和跨侧自动选择。旧偏好读取时按右侧使用，不改写历史冻结快照、版本或哈希；旧结果解码保留以支持历史回放。
- 新左右侧策略任务统一使用 entry-v2，仍检查 Worker 就绪与策略能力。升级前已受理的右侧 legacy 任务保持原始请求体和幂等身份恢复。
- 有合格正式计划时维持原计划及提醒流程。没有合格计划时，后台附加 `conditionalWatch`，客户端展示对应侧的条件预案卡；三语言报告也包含预案。
- 左侧预案说明触及参考区域、收回及后续收盘跟进；右侧说明收盘突破、后续回踩守住。优先使用有效的原策略右侧触发参考，否则明确标记最近 20 根已收盘 K 线的区间参考，不能称为原生确认信号。
- 卡片列出当前未满足项、做多／做空参考条件、确认步骤、到期与失效条件。模型失败或行情缺失、断档、过期、扁平时保留卡片及待满足项，不捏造触发价。
- 条件预案是尚待复核的只读计划。价格触发后须重新核验策略、账户风险、费用、净盈亏比及入场／止损／止盈，不能直接添加为可执行入场提醒。既有合格条件计划仍按原流程添加和启用提醒。一般解释与持仓管理不凭空产生新入场卡。
- 减少动态效果时逐个显示静态绘图对象，每个对象默认约 260ms、最快至少 160ms，不移动或闪烁光标。常规逐笔播放保持，取消及切换代际校验继续生效。
