# Binance 账户绑定出口恢复

2026-10-20，生产故障修复。正式 Windows 0.1.176 的源码基线为 08cc4fd；本次修复版本 0.1.177，接续实际已发布版本。Git 基线中的 0.1.181 是此前开发编号，0.1.176 为用户明确指定的正式版本。

## 已确认的问题

本地 Binance 请求治理器在直连出口冷却或预算耗尽时，只有公共行情备用回调。账户请求被治理器提前返回 429，无法到达健康的私有代理。可控复现返回 429，备用传输调用次数为零。私有路由也未将 418/429 视为需要切换的直连故障。

账户读取现在配置独立私有备用回调；只允许 GET、固定 Binance 目标，通过既有授权私有隧道传输，保留端到端 TLS 和签名。签名请求不会进入公共缓存。直连 418/429 持久化原出口冷却，再由账户服务重新校时、签名后使用备用出口。备用出口自身的拒绝原样返回，不继续尝试被封的直连出口；明确 direct 模式仍关闭备用。

## 验证与边界

- 71 项账户、治理器、路由和私有隧道测试通过，含真实账户服务代码的完整模拟绑定：冷却、预算耗尽、418、429、连接重置；无真实 API 凭据或交易请求。
- 原出口冷却保持；备用出口限频、GET/目标限制、取消及凭据不进入公共回调均通过。
- 类型检查通过。生产包还需 EV 签名、安装内容比较、启动验证和更新渠道验收，不能以源码测试代替发布完成。
- 当前机器绑定国内物理网卡且保留 Codex 的 VPN：私有代理 readiness 200/约109 ms，Binance 直连 TLS 被重置。仅证明该机器的可达性，不代表所有运营商，也不是实际用户带凭据绑定验收。
