## 根因与改动

原任务不是图层隐藏或画布没有执行：云端威科夫引擎在模型复核前就没有产出区间，之后独立条件计划兜底成功，因此只有交易价位线和“结构尚未确认”便签。原始 100 根窗口漏掉箱体前段；更关键的是候选仅从最近几个固定端点取窗，将突破后的高点吸收到箱顶，导致上沿触点不足。单纯加 K 线只能部分改变结果，仍可能画出被突破污染的箱体。调查证据见 [M1-439](wyckoff-missing-range-20261022.zh-CN.md)。

1. `wyckoff-range-lifecycle.mjs` 按已收盘前缀扫描不同长度的形成区间，出现突破时冻结支撑、阻力、容差、形成结束点和区间 ID；后续价格不再参与该箱体边界计算。当前可用历史中的旧箱体与新箱体共同排序，而不是要求当前价格还在旧箱体内。
2. 形成质量要求上下边界各有独立触点、至少两次上下边界转换，以及原有宽度与包含率门槛。相邻收盘涨跌换向频率仅用于评分：缓慢完整的箱体往返不会再被微小涨跌频率门槛误杀，趋势中的交替小波动也不能替代边界往返。
3. 突破、回踩、失效和再次突破分开记录。多空对称处理 SOS/LPS、SOW/LPSY；回踩不再受固定末端偏移限制。价格回到箱内／穿过结构止损后，原突破与回踩失效；后续新突破必须重新建立事件链。
4. 未收盘事件只作待确认。阶段 D/E 和交易候选只使用已确认事实；保留二次测试、事件时效、距离、量价与风险约束。新事件和旧失效事件不会相互覆盖。
5. 绘图矩形截至冻结的形成结束点，上下沿延伸用于观察后续回踩。事件选择保留最新突破及回踩；实际突破、期间最高／最低点、已确认回踩之间画出有行情证据的折线，未确认回踩单独标记。Drawing v1 只支持 confirmed/tentative，因此失效图元使用待确认样式并明确标“已失效”，避免协议把 unknown 状态默认变成 confirmed。TheoryResult 保留 invalidated 原始语义。
6. Windows 新威科夫请求增加 `preferredWindowCount=240` 建议历史，仅在没有显式时间窗口时使用。服务端保留原请求的严格最少数量，上市较晚但满足原数量的市场使用实际可用历史；显式 lookback 优先。快照 ID 绑定实际窗口，旧任务重试仍用冻结快照。此项是形成上下文补足，核心修复在生命周期算法。
7. 云端固定引擎副本同步至 0.2.0，更新来源清单及哈希；保留既有语言、模型复核、Drawing Gateway、独立交易计划与风险架构。没有修改全局交易风险算法，也没有把形态识别分数当作统计概率。
