# M1-377 订单流分析数据窗口修复

## 根因与修复

2026-10-19 02:11:51 本机 `turn-diagnostics.jsonl` 记录订单流 BTCUSDT 永续 1 小时分析在约 3 秒内返回 `MARKET_HISTORY_INSUFFICIENT` / HTTP 409。云端化后的官方 UI 目录已移除私有 `dataRequirements`，主图及分屏默认只传 100 根 K 线；订单流和道氏理论要求至少 120 根且 119 根已收盘。此前直接 SDK 检查不传窗口，服务器取 600 根，因此未覆盖实际 UI 请求。

客户端现在在主图、捕获图表和分屏入口使用公开历史数量下限，Host 在创建新快照前再次按服务器能力信息校验。旧 API 尚无该信息时使用兼容下限；不改变 VPVR 的真实可见区间或用户指定的时间范围，不重写已保存请求、幂等键、市场身份或交易偏好。

复核还发现云端任务的 `error` 可能是字符串，旧代码只读取 `error.code`，导致错误被归为“分析流程未能完成”。现在保留有界的机器错误码，并为历史不足、订单流成交／盘口不可用、市场不支持和数据窗口不兼容提供简体中文、英文、繁体中文解释；原始上游文本不进入用户提示。

后端把既有准入规则提取到统一模块，由准入和能力查询共用，提供总 K 线、已收盘 K 线和推荐窗口数量。准入阈值保持不变，数据不足仍在创建任务和计费前拒绝。没有迁移策略私有算法到客户端。
