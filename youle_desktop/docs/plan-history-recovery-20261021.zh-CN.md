# M1-425：Windows 历史会话计划卡片恢复

状态：已完成本地源码修复、回归与开发版历史读取验收；未提交、打包或发布。

## 原因与现场证据

历史加载只从 `dynamicToolCall` / `mcpToolCall` 的工具结果恢复原生展示项。新版执行器的工具输出可能被包装、压缩或经 code-mode 截断，历史读取无法再按原协议提取 `presentationItems`。文字最终回答仍在，因此界面出现“计划卡已显示”的正文，却没有计划卡。

原始卡片没有丢失：Host 的 `trading-skill-results` 已按账号、会话和 analysisRef 保存成功展示结果，但历史加载没有使用这份持久数据。截图对应会话的裸K、威科夫结果都保留完整原始报告、价格、三档止盈及云端计划回执。只读检查还观察到 code-mode 历史输出的明确截断标记。

## 修复

- 在交易 artifact 存储中增加成功展示项索引，只读取 `effects.present.presentationItems`，不把未展示的分析自动生成卡片。
- 校验文件哈希身份、账号和会话，异步读取后再次核对当前账号。损坏或不属于当前会话的文件不会串入卡片。
- 主动读取、后台预加载及缓存读取在旧版 transcript 恢复后合并持久卡片，按消息 ID 去重，保持原轮次归属及最终回答。已经压缩的轮次只在 UI 侧恢复原展示项，不向执行器写入新的用户消息。
- 保留 `__youleNativeResponseComplete=false`，展示卡片不会提前结束主回复。兼容原生文本块命名差异。
- 缓存仅保留展示项；原子写入及目录变更会使缓存失效。恢复不调用模型、绘图、保存计划或激活接口。

- 本机 25 个会话、28 条成功展示结果回放，共恢复 26 张可显示卡片；原本没有可执行卡片的结果保持原样。截图会话两张卡片均恢复，失败数为 0。
- 94 项相关自动测试通过：重启、缺失／截断工具输出、前台／后台读取、旧 transcript、账号隔离、读取中切换账号、文件身份、损坏文件、去重、缓存刷新、压缩轮次及原生文本协议。
- TypeScript 类型检查、Vite 隔离构建通过；仅既有 bundle 大小提示。
- 正在运行的开发版在本次验证时已加载修复。真实历史会话的无障碍树确认裸K、威科夫卡片各一张；威科夫入场 83238.20、止损 81232.70、三档目标 84273.50 / 84506.30 / 85057.20 及“添加到计划／放大／缩小／便利贴”按钮恢复。
