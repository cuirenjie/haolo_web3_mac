## 结论与证据边界

两张截图不能被认可为“同一谐波候选直接推导出的完整交易计划”。两张图都是看涨反转的发展中结构，向下虚线表示尚待形成的末腿及潜在反转区，并非已确认的看跌信号或必达止盈目标。源码可确认存在通用价格结构兜底：原策略没有可执行方案时，仍能生成区间交易计划，保留谐波形态图。这种计划可以有自己的价格结构逻辑，但不能据此声称它满足图上 Crab/Shark 的入场规则。

尚未取得两次真实任务的冻结 K 线、runId、候选 ID 和完整回执；未读取线上运行文件。因此，本报告区分“源码及隔离复现确认的机制”和“截图高度吻合但尚未逐任务锁定的归因”。不声称已重放这两笔原始任务，不把本地源码检查当成线上版本验证。

## 源码确认的问题

### 1. 谐波原生等待被通用完整计划兜底替换

- `src/main/trading-analysis/harmonic-pipeline.mjs:125` 的 `buildHarmonicDevelopingActionPlan` 只输出方向、waitZone、`disposition: wait`，没有入场/止损/目标；`runTradingHarmonicAnalysisPipelineInternal` 的 developing 分支不调用模型。
- 业务后端 `app/mobile/complete_entry_plan.py:92` 对成功完成但没有原生计划的 wait 结果，按 20/40/80/160/240 根已收盘区间构造候选，并按距离当前价格排序；无 PRZ 或谐波候选绑定检查。
- `app/mobile/left_conditional_fallback.py:56` 的 shared 路径允许谐波等策略使用通用区间，低边生成多头、高边生成空头，目标来自对侧区间。
- `complete_entry_plan.py:131` 自身明确记录 `source: closed_price_structure`、`sourceStrategy: harmonic`、`nativeSignalConfirmed: False`。这是独立计划来源，不能当成谐波信号已确认。
- `app/mobile/entry_projection.py:66` 保留原生形态绘图、替换交易水平线；同文件约 133 行用通用计划报告覆盖原始谐波报告。报告虽有“不是原策略确认”的说明，截图中的形态与“谐波形态”卡片标签仍容易让用户认为同源。
- ADR-059 曾要求无原生信号时仍保留完整条件计划；本轮不撤销既有产品要求。需要修正的是来源、图形、条件和命名的一致性，不能将通用兜底等同于严格谐波方案。

### 2. 发展中候选缺少反向突破后的失效检查

- `harmonic-engine.mjs:565` / `harmonic-subengine-common.mjs:67` 的 progress 只取朝预测终点方向的极值，限制路径进度 8%–120%；没有检查途中是否反向突破原 C/B、甚至原 A。
- `evaluateClassicDevelopingCandidate` / `evaluateSharkDevelopingCandidate` 因而可继续接受旧锚点，PRZ 保持不变。
- 隔离反例：Crab X=100/A=200/B=138.2/C=186，之后先回落、再上涨至 220、再回落到 160；旧 Crab 仍通过。Shark 0=100/X=200/A=150/B=215，之后涨至 260、再回落到 190；旧 Shark 仍通过。多空镜像共四例均复现。
- 反例输出 `.cache/harmonic-audit-20261022/counterexamples.json`；复现脚本同目录 `reproduce.mjs`。仅验证漏洞，不是用户行情回放，也不是通过了策略有效性验收。

### 3. Shark 完成比例的测量基准与原始资料不一致

- 当前 `harmonic-shark-engine.mjs:39` 使用 `abs(C-X)/abs(X-0)`；140 行起的发展中投影也从 X 按 0X 投射 0.886 / 1.13。
- Scott Carney 原始 Shark 演示文稿第4页的 PRZ 标为 0.886 0B / 1.13 0B，第15页结论再次明确 0B。与当前 0X 公式不是同一个价格基准。
- 需要明确采用的定义，并按原始端点统一公式、规则文档、黄金样例及测量标注；在此之前不能认证图2精确 PRZ 已严格符合 Carney 原始规则。
- 此处不根据低精度截图提供“修正后”的数值区域。

### 4. 统一风控价不是谐波结构失效价

- `app/mobile/entry_stop.py` 最小止损距离为入场价 1%，按最小精度向外取整。
- 隔离代入截图入场和常见价格精度，得到 ETH `2430.04 × 0.99 → 2405.73`、BTC `84875.2 × 1.01 → 85724.0`，与截图一致。这是规则吻合证据，不是原任务调用链回执。
- `app/mobile/left_target_stop.py` 还按净风险档位选择摆点或分配结构空间，目标一/二/三不必来自谐波回撤比例。其数值可有通用风险依据，但不应当作谐波目标依据。

## 规则依据与适用边界

- [Scott Carney：Crab](https://harmonictrader.com/harmonic-patterns/crab-pattern/)：核心完成区域由 XA 1.618 延伸和 BC 延伸收敛。发展中末腿不保证必达。
- [Scott Carney：Shark](https://harmonictrader.com/harmonic-patterns/shark-pattern/)：在完成区寻找反应，强调即时反转行为和主动管理。
- [Harmonic Trader 原始 Shark 演示文稿](https://www.sr-analyst.com/Shark.pdf)：第2页讨论 50% 管理目标；第4/15页标明 0B 完成测量。该文稿为原作者材料的外部托管副本。
- Haolo 规则文件 `resources/trading-strategies/builtins/harmonic/references/rules.md` 规定经典形态目标为 D→A 38.2%/61.8%，Shark 为 C→B 50%/61.8%，以及 Terminal Bar 后收盘确认。这是产品冻结的执行口径，不声称所有谐波交易者都必须采用相同确认、目标和容差。
