# M1-467B 前置气泡统一展示节奏

2026-10-26。用户确认首条回执已经保留，追加要求三条前置气泡以相同秒数依次出现，避免理解请求和云端提交几乎同时弹出。

## 行为

- 第一条“收到，我正在准备处理你的请求。”立即显示。
- 理解请求、向云端提交两条前置进度按统一 1000ms 展示间隔依次追加。间隔从上一次 DOM 更新结束计时，避免首帧完整渲染消耗掉第一段阅读时间。实际视觉间隔还受渲染调度影响。
- 仅对本轮已产生的本地前置进度排队；真实进度迟到时等待真实消息，下一条仍间隔 1 秒，不按过期时间一次性补齐，也不编造阶段。
- 后台分析、画线及持久化照常执行，不等待气泡定时器。若完整结果提前产生，展示层让三条前置气泡先呈现，第三条保留一个阅读间隔后再展示后续结果；完成状态不能提前折叠尚在展示的前置气泡。
- 停止、错误、无第二条前置进度的失败直接解除排队。历史重开不重新播放；会话 ID 迁移继续原节奏，切账号／离开会话的旧定时器不会刷新当前会话。普通回复、群聊及没有本轮回执的历史消息不新增延迟。

实现位于独立 `trading-prelude-pacing.ts`，主入口仅装配投影、刷新和取消。原始消息、内容、顺序及模型输入不因展示计时改写。保留 M1-467A 的首条回执和本机账号隔离存储。五语客服候选同步更新，无新增代操作协议。

- TypeScript 检查通过；Vite 隔离构建通过（既有大块提示保留）。
- 实际 Electron：新会话策略分析与后续指标分析共六条气泡；两轮间隔分别为 1202.6／1026.4ms、1126.5／1022.4ms。测试允许渲染调度误差，但没有同时出现的前置气泡。首条 DOM 延迟 245.1／130.7ms，原 250ms 门槛在该次运行通过；不据单次测量承诺所有设备的首帧耗时。
