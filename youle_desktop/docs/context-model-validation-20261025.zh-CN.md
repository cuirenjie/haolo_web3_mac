# 真实模型、连续性与计费对照（2026-10-25）

最终决策：保留同结果长文本去重和当前会话背景排除；撤回 128K 提前整理。最终方案的 26 个答案通过本次事实、权限与连续性检查。试验规模有限，不能宣称所有策略、用户历史和每次调用都无退化或固定省积分。

- 长历史试验运行客户端自带 `haolo_ai.exe app-server`，使用隔离目录及真实原生历史注入、整理和续接；没有把普通 HTTP 拼接伪装为原生整理测试。

- 另有一次 502：保留失败目录，账单查询为 0 条、0 积分。随后独立启动了一个新审计批次，没有把失败请求混入成功样本。

## 对照结果

“输入”包括缓存与未缓存；积分取实际账单，不用字节数或 token 单价估算替代。

## 分析质量与连续性检查

结构化断言覆盖市场及周期、触发/失效/目标价格、观察和到期时间、条件与快照 ID、最新 revision、已有 SHORT 仓位及实际入场价、未知数量与保护单、分析授权和未完成事项。后续更正只更新指定价格；撤销候选计划不能变成已平仓、已下单或已知零仓位。同组任务待办 `D-741` 在背景排除后保留。

逐条复核最终 explanation：两组均区分盘中刺破与收盘确认、候选入场与实际仓位、未知保护单与已有保护措施；保留最新修正，不采用已废弃版本。此处验证的是已读冻结证据的推理及跨轮跟随，不代表全套量化策略、实盘预测能力或真实交易执行已经评测。

长历史初次评分曾把“撤销候选计划”对应 action 强制判成 CANCEL，但题目同时要求“所有其他字段保持”，原 action 是 WAIT。基线解释已明确撤销计划并等待核验保护单，不能把此项算作退化。新批次使用同一问题，只修正评分：action 保持 WAIT，独立检查撤销说明。旧 `results.json` / `summary.json` 原样保留，没有覆盖或挑选成功答案。

提前整理仍有独立失败：优化组的后两次回答将 conditionId、trigger、target 置为 null，违反保留其他字段要求；基线保留了原值。整理摘要本身包含这些字段，因此不能断言摘要删除了事实；可以确认的是整理后的回答行为出现差异，候选未通过质量门禁。磁盘历史两组均完整，磁盘完整并不能保证模型回答无退化。

## 单个纯 @ 策略/指标是否需要历史

本次代码核查发现 M1-429 已实现该优化，并非本次新增：桌面交易会话空闲、完整匹配一个启用的官方策略/指标 token、无正文/附件/引用/待续业务时，`resolvePureTradingAnalysis` 进入固定通道。发送时冻结当前图表、市场、周期和模型；保存用户消息后直接执行云端分析，不调用根 `sendAgentText`，不触发旧聊天整理。完整报告保存回原会话，方便以后文字追问。

云端官方策略/指标在 `agent.py` 提前分流至 `price_action.process`，不经过其后为旧 range/trend 保留的七轮历史拼接。该路径根据当前行情、账户授权、结构化偏好及量化证据构造 review prompt；taskId 用于归属/计费/缓存标识，不自动恢复聊天。K 线历史是本次分析证据，应保留，不能与旧聊天混为一谈。

因此单个纯引用可以且应该不带旧聊天，但不应删除本次策略参数、新行情、账户安全约束或结构化偏好。多个 @、附带文字（例如“比较上次”）、附件、引用和正在运行/排队的任务目前回到普通流程；多引用扩展需要单独定义是独立多份报告还是交叉综合，不能在此静默改变语义。此次没有扩展这些业务边界，没有修改云端策略算法或协议。

实际发送/运行器测试已覆盖长历史旧会话、纯策略、纯指标及普通正文回退；本轮补齐并行云任务入口引入后的 VM 夹具依赖，原断言不变。120/120 定向测试、40 项传输/整理生命周期测试、3 项客服 JS 测试、两仓各 4 项客服 Python 测试及 TypeScript 检查通过。客服测试首次缺少 TS 转换参数，补上 `--experimental-transform-types` 后通过，无需改动产品代码。纯引用核查属于源码与本地真实函数验证，未把夹具耗时当作真实模型省分数据，也未确认投诉用户安装版本是否命中此通道。
