状态：实施与分阶段验收中；尚未重新发布服务端，Windows 0.1.181 不发布。

## 冻结要求

用户要求右侧交易沿用迁移前策略与执行卡片，只改变执行位置。行为参照固定为 Windows Git `b79ec878e78c407cae5fda219ddcaa0b6a431f6f`，不得用修改后的实现重新录制期望结果。旧版源码只作为仓库 output 下的只读测试夹具，所有客户端修改、启动、构建、测试及提交均从固定 Windows 仓库执行。

新客户端在偏好为 `right` 时显式请求 `right-legacy-v1`。服务端执行原策略和原偏好读取语义，返回原始报告、执行计划和绘图；不经过 Entry V2 候选选择、二次模型决策或计划/卡片重写。`left` / `auto` 及旧客户端原协议维持现有路径。已经提交的旧 V2 任务按原任务 ID 和冻结协议恢复，不能因升级重新计费。

这里的“完全一致”指相同行情窗口、偏好、账户快照、模型选择、模型返回及时间基准下的原策略行为、结果字段和卡片 HTML 一致。实时行情变化或模型本身的非确定性仍可能导致两次独立运行的文字不同，不能用不同时刻的两次在线调用作为逐字一致证明。

## 独立完整链路

测试通过真实 Windows `YouleApiClient` 和云端运行器，经 loopback HTTP、后端鉴权夹具、独立 PostgreSQL 任务队列、私有引擎、发布事务回到客户端；对照原版策略协调器、原卡片解析及原渲染函数。账户与模型使用受控数据，不进行真实支付、交易下单或推送。

比较项目包括：报告与叙述、原生计划、方向、入场/止损/各止盈、仓位与杠杆、有效期、模型复核提示词与推理档位、主图/副图、卡片标题/正文/HTML、添加动作、便利贴亮暗主题、历史保存与恢复、云端计划绑定、激活幂等、暂停/恢复/结束/删除、账户隔离、同意授权与保留期后的恢复。

17 个策略分别覆盖简中、英文、繁中，直接输出/模型复核及行情镜像；另覆盖没有机会、账户未绑定、账户不可用、账户资金与已有仓位。持仓管理单独比较，不能替换成开仓策略。

## 深度复核修正

- 原迁移的右侧仍调用 Entry V2，会改变方向、候选、止盈数量和卡片；现在使用独立的原版兼容协议，并以全部活跃 Worker 的能力检查控制开放。
- 通用移动偏好转换与原 Windows 的字段作用域、默认值和旧字段优先级有差异；右侧使用固定原版纯函数，保留止损距离、模糊旧字段及自定义硬约束的原含义。
- 恢复原策略协调器追加的偏好上下文及旧版模型复核 developer 指令，移除只在新服务层加上的额外偏好提示与输出字数上限；原移动/V2 请求不改变。
- 原卡片的监控价位来自格式化后的卡片文本和第一个目标，不等同于未舍入的原生计划价位；服务端沿用原解析器，不重新计算。原有不可激活卡片仍保留展示，不能凭空生成可执行规则。
- 双向卡片与不同图表中相同文案分别绑定自己的云端计划 ID；恢复单张卡片时保留整份原始报告。拒绝重复 ID、错误语言、过期时间、上下文或价格篡改。
- 原副图分析 ID 可能与主图不同，不能按新合同错误拒绝；保留原绘图并通过原客户端绘图校验。
- 原已提交任务继续使用冻结协议；提醒使用原 `windows_v1` 行为，禁止在生命周期操作中切换到 Entry V2。
