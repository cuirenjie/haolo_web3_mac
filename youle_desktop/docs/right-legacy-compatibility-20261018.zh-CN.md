## 深度复核修正

- 原迁移的右侧仍调用 Entry V2，会改变方向、候选、止盈数量和卡片；现在使用独立的原版兼容协议，并以全部活跃 Worker 的能力检查控制开放。
- 通用移动偏好转换与原 Windows 的字段作用域、默认值和旧字段优先级有差异；右侧使用固定原版纯函数，保留止损距离、模糊旧字段及自定义硬约束的原含义。
- 恢复原策略协调器追加的偏好上下文及旧版模型复核 developer 指令，移除只在新服务层加上的额外偏好提示与输出字数上限；原移动/V2 请求不改变。
- 原卡片的监控价位来自格式化后的卡片文本和第一个目标，不等同于未舍入的原生计划价位；服务端沿用原解析器，不重新计算。原有不可激活卡片仍保留展示，不能凭空生成可执行规则。
- 双向卡片与不同图表中相同文案分别绑定自己的云端计划 ID；恢复单张卡片时保留整份原始报告。拒绝重复 ID、错误语言、过期时间、上下文或价格篡改。
- 原副图分析 ID 可能与主图不同，不能按新合同错误拒绝；保留原绘图并通过原客户端绘图校验。
- 原已提交任务继续使用冻结协议；提醒使用原 `windows_v1` 行为，禁止在生命周期操作中切换到 Entry V2。
- 混合恢复旧 V2 与新右侧卡片时，按各自协议展示并保留独立操作索引，避免漏掉旧卡片或按钮指向错误计划；两种排列顺序均有回归。
