# DSML-COMPAT-20261025：DeepSeek 工具协议与旧会话兼容

本任务修复 Windows 客户端中模型协议文本直接显示的问题。修改位于规范仓库，未发布安装包、未部署后端或网关，也未重放投诉用户的请求。

本文保留首次修复的验收记录。未声明工具名的当前恢复行为以末尾 **DSML-RECOVERY-20261025** 追加说明为准。

## 原因与处理

截图中的 DSML 是模型输出的工具协议文本，不是中文字符集损坏。仅将旧模型名称替换成 DeepSeek，仍会留下原生运行时的 namespace、tool_search、additional_tools 和旧 custom exec 历史。DeepSeek Responses 的受支持工具和输入格式与这些对象不同，模型可能无法发现实际业务工具，随后把调用语法作为普通正文输出。

依据：[DeepSeek Responses 接口](https://api-docs.deepseek.com/api/create-response/)、[Responses 兼容说明](https://api-docs.deepseek.com/guides/responses_api/)。模型函数名称上限为 128 字符，工具声明必须唯一；custom 仅支持 apply_patch。接口无服务端历史存储，客户端需携带历史。

新增 `src/main/deepseek-responses-adapter.mjs`，只在 `deepseek-flash` 的 HTTP Responses 传输边界转换请求副本及响应：

- 将 namespace 中的 function 展开为稳定且可逆的名称；schema、arguments、call_id 和业务 context_id 原样保留。
- 将原生 tool_search 声明映射为普通 function；返回后恢复原生发现事件，让既有运行时执行发现。发现结果中的声明加入后续模型请求。未声明、已移除或格式错误的工具调用不获得执行权限。
- 将旧 custom exec、缺少有效 reasoning 的历史调用和回复转换为明确标注的历史证据。保留工具输入、输出、图片及调用关联；不解密旧推理、不执行历史代码、不修改原始 rollout。
- 保留 DeepSeek 当前推理、调用和结果的配对，支持原有压缩与计费路径。其它模型传输、业务 API、云端分析和交易执行器未因本任务改变。
- 跨 SSE 分片识别 DSML；只暂存可能属于协议标记的前缀，正常文本和进度继续流式传输。DSML、破损调用及恢复阶段再次调用工具等异常以 `MODEL_TOOL_PROTOCOL_ERROR` 终止，禁止自动重放业务。没有把 DSML 解析成可执行工具。
- 历史正文显示时隐藏泄漏协议及后续代码，保留此前正常文字，显示简体／繁体／英文异常说明。底层原始记录保留。
- 修正请求取消时数字型 `AbortError.code` 被当作字符串调用的异常，取消后 relay 仍可服务。

## DSML-RECOVERY-20261025：未声明工具名的有界恢复

### 根因与修复范围

原异常证据为 `dsml-1792867152327/requests.json` 的第 14 个上游回复。前一请求已经取得 `haolo_analysis` 的持仓证据，上游仍生成结构化 `function_call`，名称为 `haolo_not_needed`。对应请求的工具声明不包含这个名字，产品源码和随包提示也没有该名称。这是上游生成了清单外的调用；上一版客户端将它直接归入不可恢复协议错误，使已取得的证据没有生成最终回答。

本次仅对格式完整、参数为合法 JSON 对象、调用 ID 存在的清单外 `function_call` 提供错误反馈。不会猜测相似工具名、放宽业务权限或将其转换成真实业务调用。

### 恢复过程

1. 适配层将清单外调用转换为一个随机的、未注册的原生函数名，携带 `HAOLO_TOOL_NOT_EXECUTED`、原名称及 `executed:false`。原生运行时走既有 unsupported-tool 路径生成匹配 call_id 的错误结果；没有新增业务处理器，没有实际执行该调用。
2. 同一原生轮次自然继续推理，保留已完成工具的结果、回执、时间和限制。原生运行时负责收齐同一批并行调用的结果，不重新发起用户请求，也不重新调用业务 broker。
3. 后续模型请求强制 `tools:[]`、`tool_choice:none`、`parallel_tool_calls:false`，追加只根据已有证据完成文字的约束。响应端也拒绝所有工具调用类型，防止上游忽略请求约束。
4. Host 按 thread_id／turn_id 保存只允许回答的状态；历史整理或摘要替换不能重新打开工具。重复开始通知、旧轮次完成通知和其它会话均不能清除当前限制。当前轮次完成／取消、关闭会话或停止运行时会清理状态；新的用户轮次恢复正常能力。
5. 最多一次这样的文字恢复；再次返回工具调用、DSML 或破损协议仍明确失败，不进入恢复循环。权限、余额、网络或业务错误不因本机制而重放。未取得的证据和未执行的操作必须如实说明。

恢复会增加一次正常计费的模型推理，但不会因此重复付费业务分析或其它业务操作。它解决“已有结果因不存在工具而无法交付”的情况，不保证在证据缺失时自动补齐所有工作。
