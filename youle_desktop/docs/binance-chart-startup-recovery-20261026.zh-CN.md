# K 线首次加载自动恢复与公共行情选路修复

## 已确认的问题

公共行情自动选路原来在收到 HTTP 响应头后就确定获胜线路、更新线路偏好并取消备用线路。正文随后断流、截断或无法解析时，错误发生在外层请求调度器或行情服务，无法再触发同一次请求的线路接管。已认定健康的直连和已记住的网关也存在同样的正文失败缺口。

修改前通过原样 Router → Governor → PublicMarketService 隔离复现：直连或网关先返回 200 响应头，随后正文中断，首次请求返回失败，第二次完整响应成功；直连失败后仍有约 30 秒健康租约。用户未保留原始报错与请求标识，因此本次修复针对已复现缺陷，不把它认定为所有历史红框的唯一根因。

## 修复

- 自动选路的正常成功响应先完整读取、解析 JSON，再参与选路或刷新健康状态；K线和逐笔成交接口校验顶层数组。价格、周期、历史完整性与分析新鲜度继续由既有消费层校验。
- 正文读取使用既有 16 MiB 上限，不通过 tee 网络流进行额外解析。断流、截断、无效 JSON 及错误顶层类型均进入原有备用线路处理。
- 自动模式的直连 3 秒尝试时限覆盖正文；K线/逐笔成交的网关尝试默认最多 10 秒，为直连接管及主图 30 秒窗口内重试保留时间。较大元数据继续保留较长预算。
- HTTP 错误与明确标记的 stale 候选仍先检查状态，避免为读取卡住的错误正文阻塞健康直连。若最终使用这类回退响应，其正文继续由请求调度器按原预算读取。304、鉴权错误、交易所限流冷却、明确指定线路模式及私有账户通道保持原语义。
- 主图首次打开、切换周期或市场保留 30 秒自动重试，默认失败后间隔 1.5 秒，尊重服务端冷却；超时取消在途请求，切换/销毁取消旧加载，手动重试建立新窗口。启动阶段由主加载独占历史恢复，防止 WS 重连额外启动竞争请求。
