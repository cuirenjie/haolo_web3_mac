# Windows 首次安装桌面快捷方式修复

日期：2026-10-22。状态：三处复审遗漏及剩余翻译审计失败均已修复，完整相关回归 84 项全部通过。未打包、未发布、未升版本。

## 问题及证据边界

用户反馈首次安装后可以使用客户端，但桌面没有快捷方式。当前 electron-builder 的 NSIS 创建流程在 `CreateShortCut` 后清除错误；原有自定义刷新和客户端启动修复仅处理已经存在的链接。这使首次创建失败可以被忽略，而且后续没有可靠的补救授权记录。

已验证这个失败路径，尚未取得反馈用户当时的桌面路径、权限或安装日志，不能据此确认其具体触发因素。

## 实现

- `resources/installer.nsh` 在卸载旧版及重写安装注册表之前记录两个安装范围的状态。更新识别同时检查 HKCU 和 HKLM，保证当前用户与所有用户的同目录手动覆盖安装都传递 `--keep-shortcuts`；带 `--updated` 的自动更新以及卸载器自身参数语义保持不变。
- `resources/windows-desktop-shortcut.ps1` 是安装器和客户端共同使用的策略与 Windows ShellLink 写入器。通过系统目录 API 获取当前用户或公共桌面，支持重定向目录；校验目标、图标及 `local.haolo.desktop` AppUserModelID，最多尝试三次。
- 有效链接无需更新时不重写。快捷方式创建失败会显示安装器重试提示；静默安装以非零退出码报告问题。原有直接启动主程序的方式保留。
- 持久状态在对应 HKCU/HKLM 的 `Software\HaoLo\DesktopShortcut\d4c2c60d-33e6-5907-bc77-3ad20bbc60d5`，不放在旧卸载器会删除的安装信息键内。完整卸载清理它，更新保留它。
- 每次写链接之前先保存 `attempting`，成功后保存 `verified`。只有明确失败且链接不存在的首次创建或用户主动创建操作才留下可重试的 `pending`。写入或确认结果不明确时停止自动补建。
- 启动时只消费与账户、安装范围和目录匹配的 `pending`。已成功创建后被删除、旧版缺少快捷方式但没有失败记录、用户选择不创建，都不自动补回。更新中断导致旧程序或安装信息丢失时，仍保留已有的不补建状态。
- 安装结束时在互斥保护下重新读取最新状态与链接，不重复消费快照中的创建授权。已有链接只允许原子替换，删除后不退回创建；文件已发布但验证失败时也不重试补建。删除状态确认失败同样不会进入创建重试。
- 桌面旧中文名称由安装器受控迁移：无删除记录且原链接仍存在时原子改名，失败不先创建副本。客户端启动仅迁移两个开始菜单，不再通过残留旧桌面链接补建 HaoLo 图标。
- 设置增加“创建桌面快捷方式”按钮，作为明确的手动补救入口；有效公共桌面链接可直接复用，避免重复图标。简体中文、繁体中文和英文均已覆盖。
- 诊断文件为 `%LOCALAPPDATA%\HaoLo\logs\desktop-shortcut.jsonl`，记录操作、范围和结果，限制文件大小，不包含聊天或凭据。

## 2026-10-22 再次审查记录（以下三处现已修复）

该轮只审查并补充隔离复现，没有修改业务代码；用户随后授权修复。以下保留当时的反例和原因，当前实现与验证结果见上文，不代表实际 Explorer 固定图标的端到端验收。

1. **所有用户安装的手动覆盖更新可能取消任务栏固定。** `installer.nsh` 的 `_haoloIsUpdated` 只检查 `--updated` 和 HKCU 安装位置。如果原来只有 HKLM 的所有用户安装，双击 Setup 手动覆盖时判定为非更新，不会向旧卸载器传递 `--keep-shortcuts`；上游卸载器因而进入 `WinShell::UninstAppUserModelId` 分支。这是原有兼容逻辑的缺口，并非本次新增，但仍不符合此次验证目标。隔离 NSIS 诊断结果：当前用户手动/自动更新及所有用户自动更新均带保留参数；所有用户手动更新输出 `false|/allusers`，缺少该参数。需要覆盖 HKLM 已安装状态，并增加该模式的回归测试。
2. **安装开始后的删除会被旧快照覆盖。** Snapshot 在安装器初始化时记录链接；Install 只使用该快照做决定，没有复核已消费的修复授权及链接最新状态。真实 `.lnk` 隔离复现：打开安装器后删除快捷方式，安装结束得到 `verified` 且文件重新出现。另一个复现是快照含 `pending`，客户端已成功恢复、用户随后删除，安装完成仍重放旧 `pending` 并补回。需要在写入前复核当前持久状态及链接变化，不能重复消费快照中的创建授权；对原有链接的修复不能在用户删除后退回创建。
3. **旧中文名称迁移绕过不补建策略。** 客户端先执行 Recover，之后仍无条件调用 `migrateLegacyPackagedWindowsShortcuts()`。该函数只要找到旧中文链接，就创建 HaoLo 链接；不读取 `verified`、`preserved-absent` 或 `opted-out` 状态。故障注入复现：旧链接删除因权限失败后，用户删除新 HaoLo 链接，下次启动迁移再次创建。需要让桌面名称迁移遵守同一持久策略，保留开始菜单原有迁移行为。

补充复现均在临时目录运行，未触碰真实桌面或任务栏。复审时重跑原 75 项测试得到 **74 通过、1 失败**：快捷方式、更新和任务栏相关测试均通过，但它们尚未覆盖以上反例；英文无汉字审计在 `trading-plan-price-lines.ts` 的新模板片段 `做` 上失败，该文件属于当前共享工作区的其他改动，本轮未修改。

原有测试未覆盖这些反例。本次已增加对应回归：旧实现能触发快照重放和启动迁移测试失败；修复后三处反例均通过，并额外覆盖原子写入及状态确认失败。仍需按下节在获准打包后完成真实安装环境验收。

## 打包获准后的验收

尚未进行完整签名安装包验收，也未宣称真实 Explorer 任务栏固定图标已通过端到端升级验证。后续至少需要在 Windows 10/11 的干净环境验证：

1. 当前用户和所有用户首装、默认与重定向/OneDrive 桌面、中文路径；不勾选安装后启动时也应有快捷方式。
2. 已有桌面链接及任务栏固定图标情况下，自动更新和手动覆盖安装；核验图标、目标、点击启动和分组均正常。
3. 主动删除桌面链接后，重启客户端及更新均不恢复；设置中的手动创建可以恢复。
4. 限制桌面写权限时显示明确失败；恢复权限后，仅已记录的首次创建失败可以补救。PowerShell 被策略禁用、账户不匹配、公共桌面无写权限时应报告失败，不能猜测为首装或悄悄改写其他账户。
5. 完整卸载后重新首装，以及更新中断后的再次安装，核验持久状态的清理和保留。

权限或安全策略可以阻止任何程序写入桌面；实现保证可验证的创建结果和明确的失败处理，不能保证绕过这些限制。
