# 使用数据 Excel 导出接口

桌面端通过后端接口生成并下载当前登录用户的完整历史使用数据。客户端不拼接页面当前月份、时间筛选或分页结果。

## 请求

`GET /api/consumption/me/export?unit=token|usd`

- 必须使用与其他 `/api/consumption/me` 接口一致的用户鉴权。
- `unit` 是唯一业务参数；只允许 `token` 或 `usd`。
- 接口固定导出当前用户全部历史数据，不接受日期范围和分页参数。
- 导出会使用独立的历史游标从中转账本补齐上线时间之前的记录；首次全量回补可能比后续增量导出耗时更长。

## 响应

- HTTP 200
- `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- 响应体为完整 `.xlsx` 文件。
- 失败时返回现有统一 JSON 错误结构和对应 HTTP 状态码。
- 桌面端在用户确认“另存为”路径后流式写入文件，避免大体积历史工作簿全部驻留内存。

## 工作簿内容

### 用户概览

包含用户名、好咯号、累计消耗、最高单日消耗、最长任务时长、登录天数、消耗单位和导出时间。不包含头像、会员或体验版标识。

- 累计消耗和最高单日消耗只输出 `unit` 指定的单位，不混用 Token 与美元。
- 最长任务时长只统计 `status = complete` 且具有可信开始、结束时间的任务。
- 美元值使用数值单元格和两位小数货币格式；Token 使用整数数值单元格。

### 每日消耗

包含“日期”和选定单位的“当日消耗”两列，按日期升序输出全部历史数据。只输出数据库中存在实际消耗记录的日期，不补零、不生成空白日期。

### 使用明细

输出全部历史记录，不受页面“今天 / 7 天 / 30 天”和分页限制。至少包含：

- 消耗数（仅选定单位）
- 模型
- 类型
- 完整详情/问题
- 完整回答
- 状态
- 任务 ID / interaction ID
- 会话 ID、子会话 ID
- 创建/开始时间、完成时间、任务时长
- 后端记录中其他可供用户理解和核对的非敏感字段

问题和回答必须来自数据库原始字段，不得使用页面 `answer_excerpt` 或其他截断文本。不得导出服务端密钥、内部鉴权信息或其他用户的数据。

Excel 单个单元格有字符上限。任何超过单元格上限的完整问题、回答或详情必须拆分为编号连续的内容片段（可放在同表续行或辅助内容表），并用任务 ID 和片段序号关联；不得静默截断或丢弃内容。

## 生成要求

- 查询和写入均采用分页/游标或流式处理，避免一次性加载全部历史明细。
- 明细按开始时间倒序稳定排序；每日消耗按日期升序排序。
- 工作表标题行固定、冻结并启用筛选；列宽合理，长文本换行。
- 对以 `=`, `+`, `-`, `@` 开头的用户文本按纯文本写入，防止公式注入。
- 同一导出请求中的概览、每日消耗和使用明细应基于一致的数据快照或统一统计截止时间。
