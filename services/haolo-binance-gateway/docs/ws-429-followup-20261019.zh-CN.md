## 已实施修复

1. **复用连接。** 最后一个消费者释放后保留 500 ms 空闲窗口，快速图表切换复用已有通道。监听器和订阅引用立即移除，取消订阅与新订阅合并处理。
2. **先完成释放，再建立替代连接。** 通道保留正在关闭的物理 socket，新增消费者等待关闭完成；客户端自身失效 socket 最长 2 秒完成关闭，Hub shutdown 等待释放。新增订阅不能绕过已经排定的重连退避。
3. **订阅成功以 ACK 为准。** 跟踪 SUBSCRIBE/UNSUBSCRIBE 请求及 5 秒 ACK 截止；拒绝、遗漏 ACK 或断线后按当前所需订阅恢复，并申请新的一次性票据。只完成 HTTP Upgrade 不再被当成订阅恢复成功。
4. **429 正确冷却。** 消费握手拒绝响应，读取允许的错误码及 Retry-After，保留订阅需求；应用层限流和订阅错误不再使正常 DNS/路由缓存失效。
5. **网关检查失活连接。** 每 30 秒 Ping/Pong 检查，缺失响应时清理死连接及计数；正常连接和 drain 期间健康连接继续运行。连接、订阅释放幂等。租约到期立即解除订阅，物理连接计数在实际关闭后释放。
6. **补齐归因证据。** 分别记录用户并发、连接尝试频率、总连接数的拒绝计数和错误码；安全诊断使用每进程随机盐 HMAC 用户引用及随机会话 ID，记录关闭原因、持续时间和连接数量，不记录票据、Token、原始用户 ID 或完整 URL。

**没有提高连接上限：** 每用户 WS **8**、尝试 **300/分钟**、总连接 **10000**；用户 REST 权重 **300**、合约/现货出口 **1440/3600**。鉴权缓存 **15 秒**、超时 **10 秒**，行情 TTL、Redis 配额账本和完整生产环境均保持。
