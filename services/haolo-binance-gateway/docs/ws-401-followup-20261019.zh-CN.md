# M2-027：WebSocket 401 票据生命周期修复（2026-10-19）

## 证据与归因边界

- 原活动版本 `market-ws-9c67921` 的五次 WebSocket 401 均携带非空、格式正常的票据，发生于票据消费分支；该分支不调用上游业务鉴权。历史日志没有签发/消费关联记录，不能把五次失败全部确定为过期或重复消费，也不能用同 IP 后续签票证明原用户恢复。
- 本轮以失败测试确认三个客户端缺陷：票据响应跨越休眠后返回过期地址；Data Hub 使用已过期地址建连；TLS 准备期间过期后仍发送握手。三个用例在修复前均失败。
- 09:54 左右只读核验：活动指针、镜像、环境、Redis 身份均一致；WS 拒绝累计仍为五次。四个旧实例 TCP/WS 为 `40/7/3/4`，均无旧端口路由且守护器正常，尚未满足退休条件。

## 修复

- 客户端保留签票有效期，按请求开始时间保守计算本地截止时间；在返回连接信息、创建物理连接及 TLS 完成后检查。过期则关闭待用连接，走原重连流程重新签票。
- 每次重连获取新票据，只恢复当前订阅，收到订阅 ACK 后才报告连接就绪；401 分支可识别票据失效原因，不因票据失效误清 DNS。
- 网关独立票据存储通过 Redis 原子消费保持一次性使用；Redis 不可用时关闭授权入口，不回退到本地副本。保持原 43 字符票据及旧数据格式兼容。
- 短期诊断记录仅保留票据摘要、签发/过期/消费时间和客户端协议版本，无票据明文或用户身份。诊断保留五分钟不会延长授权：票据有效期仍为 30 秒。分别统计过期、已消费、未知、格式错误和存储不可用；缺少消费证据时不把票据丢失误记为重放。
- 每用户 WS 8、尝试 300/分钟、REST 用户权重 300、出口 1440/3600、缓存 TTL、鉴权及上游超时均保持原值。
