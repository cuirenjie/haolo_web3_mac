# XAU 15m 共享刷新挂起修复

2026-10-22，任务 `xau-refresh-20261022`。负责人为本次 XAU 国内直连排查会话 `01a16401-e764-7663-8019-7339b3166cf7`。用户在根因调查后明确要求“彻底修复这个问题”。本批只处理行情网关；Windows 0.1.179、业务 API、独立策略 Worker、移动端与模型网关不需要修改协议或重新打包。

故障证据见 [客户端侧调查记录](../../../youle_desktop/docs/xau-15m-gateway-investigation-20261022.zh-CN.md)。生产 `XAUUSDT / 15m / limit=501` 的共享任务没有结束，锁持续续期，客户端 50 秒超时、HAProxy 60 秒 504。不同数量与直接币安上游正常。

## 实现

- 共享刷新总预算为已有上游预算加 5 秒。缓存预读等外层操作另有已有上游预算加 7 秒的总上限；锁释放最多等待 1 秒。即使依赖不响应 AbortSignal，调用者也会得到明确的 `MARKET_REFRESH_TIMEOUT`，内存占位被释放，续租停止。
- 上游响应头与正文共享原 10 秒预算，迟到响应被清理。准入、缓存读取、冷却读取和写入、权重观测与缓存发布均处于有限的刷新生命周期内。
- 缓存发布通过 Redis Lua 同时校验锁持有者及绝对截止时间。迟到的写入不能覆盖继任任务的数据；迟到的读操作不能覆盖较新的本地缓存。清理锁只允许删除自己的 token。
- 公共行情缓存键迁移到 `rest:v2:`。滚动升级期间不等待旧版本仍在续期的锁，也不接收旧版本可能迟到的缓存。可重建价格缓存沿用原容量限额；票据、permit、账户及公共权重账本的键和限制保持原值。
- 超时日志保留固定阶段名，便于区分缓存、准入、上游响应头／正文和发布阶段；不记录交易对查询参数、用户凭据或令牌。
